# Web 控制台：localhost 浏览器管理节点（可行性评估 + 实施计划）

## 一、可行性结论：高，而且比想象的小

关键发现：**后端几乎不用新建**。节点 API（axum，只听回环 7420）已经有全部所需端点：
- `/api/status`、`/api/stats`、`/api/events`（支持 limit）→ 看板与实时事件
- `/api/config` GET/PUT → `save_config` 已实现"写回 config.toml + 热更 + 返回需重启项"（engine.rs:995）
- Bearer token 认证中间件已就位（api.rs:89）

唯一缺的是"页面本身"。方案 = axum 挂一个**内嵌单文件 HTML**（`include_str!`，项目已有此惯例 help_tab.rs:16），浏览器经现有 SSH 隧道打开 `http://127.0.0.1:17420/`。安全边界完全不变：API 仍只听回环 + token，跨机仍只能走隧道。

对比被否掉的路线：X11 转发 egui（OpenGL 间接渲染，黑屏/极慢，需装 X Server）；Windows 侧另起 web 进程（多一个常驻组件，仍依赖同一条隧道，纯增复杂度）。业界同模式先例：Proxmox/Cockpit/Grafana 全是"服务只听回环 + SSH 隧道 + 浏览器"。

## 二、体验设计（你提的两个核心诉求）

1. **实时看效果**：仪表盘卡片区（stats + 引擎/蜜罐/防火墙/AI 状态）+ 事件实时表，每 3 秒轮询刷新（v1 用轮询，不引入 SSE/WebSocket 复杂度）。
2. **管理配置文件**：页面内嵌 TOML 文本编辑器——加载当前 config.toml 原文，编辑后保存；服务端**先解析校验再落盘**（非法 TOML 直接 400 报错行，不会写坏节点配置），保存后返回"已热更生效"或"以下项需重启"清单（复用现有 restart_required 契约）。改完配置，看板 3 秒内即反映新状态——这就是"实时看效果"。

样式遵循 ui.md §8 既有 token（深邃蓝 #0B1220 底、语义色、字号阶梯），零外部依赖（无 CDN，纯 vanilla JS，符合安全工具离线原则）。

## 三、改动清单（小而收敛）

**Rust（~120 行 + 测试）**
1. `crates/aisafeguard-app/src/api.rs`：
   - 路由拆分：`/api/*` 保持现有 auth 中间件；新增 `GET /`（或 `/web`）返回内嵌 HTML——**静态壳不设 token**（页面里没有任何数据，登录框在页面内；所有数据仍走 Bearer）。这是标准做法（同 Grafana 登录页模式）。
   - 新增 2 个端点：`GET /api/config/raw`（返回 config.toml 原文）、`PUT /api/config/raw`（TOML 文本 → 解析校验 → 走现有 `save_config` 落盘+热更，返回需重启项列表）。
2. `crates/aisafeguard-app/src/engine.rs`：加 2 个小方法 `config_raw()` / `apply_config_raw(text)`（后者解析失败返回错误原文，成功返回 restart_required 列表）。
3. `crates/aisafeguard-app/src/web/index.html`（新增）：单文件控制台，token 输入一次存 localStorage，三个标签页：仪表盘 / 事件 / 配置。

**脚本与部署**
4. `scripts/asg-remote.ps1/.cmd`：隧道起来后改为**默认打开浏览器**到控制台页；`-gui` 参数仍可起 egui 远程模式（保留，不删）。
5. 构建走既有 WSL 流程（docs/LINUX-TESTING.md §1）：`cargo build --release` + `cargo test`，产出 linux 二进制。

**上线（节点侧，一次 systemctl restart）**
6. scp 新二进制到 `asg-vps:/usr/local/bin/aisafeguard` → `systemctl restart aisafeguard`（干净重启，有日志，不算实验判据里的"非正常退出"；48h pilot 计时不受影响）→ 隧道 + 浏览器验证。

**文档**
7. `docs/EXPERIMENT.md` 三点五节：远程查看正路更新为"浏览器控制台"（egui --remote 降为备选）。
8. `docs/MANUAL.md` 增补 Web 控制台章节；`CHANGELOG.md` 记条目；`docs/ROADMAP-0.7.md` 挂 F7xx 编号。

## 四、v1 明确不做的（边界，避免范围膨胀）

- 不做规则增删/建议审批/联邦面板/AI key 设置等操作功能——这些继续走 egui `--remote` 模式（它已经很全），v2 再按需搬。
- 不做 HTTPS/公网暴露——维持"回环 + SSH 隧道 + token"边界，绝不开放端口。
- 不引入前端构建链（npm/框架）——单文件 HTML，改起来就是改一个文本文件。

## 五、验证方式

- 本机：Windows `cargo test`（含新增 raw 端点测试：合法 TOML 往返、非法 TOML 400）；`cargo run` 起本地实例浏览器实测三标签页。
- 节点：部署后经隧道浏览器实测"改一条配置 → 看板 3 秒反映 → config.toml 内容确实变了"；事件页与 VPS 上 `aisafeguard export-events` 抽样对账。
- 最后更新 LESSONS.md 踩坑记录（如 axum 0.8 路由分层细节）。

风险小：改动集中在 api.rs 路由与一个新静态文件，不动引擎与检测逻辑；最坏情况回滚 = 节点换回旧二进制重启（现二进制会先备份）。
