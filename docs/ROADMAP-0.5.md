\# AI-SafeGuard 0.5 里程碑任务拆分



> 版本规划草案 · 与 `docs/ROADMAP.md`、`docs/NGFW\_EVOLUTION.md` 配套  

> 目标版本：\*\*0.5.x\*\*  

> 前置：\*\*0.4 收口完成\*\*（服务化、配置热更边界、规则 IP±端口、误报/指标、证书吊销、轻量 HTTP 标签、Windows 数据面主路径 = WFP 的决策已落地）。  

> 原则：可开关的 NGFW \*\*感知层\*\*；命中只进事件总线；封禁仍走 `Firewall` trait；默认关深检；Linux 可高速、Windows 能力对等但不强制 eBPF。

> **状态（2026-09-29）：0.5.0 完成 Batch E + F + H（P0 全部 + P1 的 E5/F7/H7）；Batch G 按发版建议归 0.5.1。** 落地对账见 docs/NGFW_EVOLUTION.md §7。

\## 0. 目标陈述



\*\*0.5 = 复用 L7/TLS 指纹 + Suricata/ET 子集规则引擎 +（Linux）可选 eBPF/XDP 加速；Windows 以 WFP 体系对等感知，处置模型不变。\*\*



威胁模型仍克制：提升对扫描器、已知恶意模式、可指纹会话的检出与可解释性；\*\*不宣称\*\*线速 IPS 替代专用设备，\*\*不宣称\*\* 100% Suricata 兼容。



设计约束：



1\. 传感器与执行器分离：规则 / 指纹 / eBPF \*\*只产事件与建议\*\*，不在内核或规则引擎内直接调用系统防火墙旁路 trait。

2\. 跨节点仍只同步建议/情报对象；N-of-M 升格情报与选举归 \*\*0.6\*\*。

3\. 自身安全：`forbid(unsafe\_code)`（自有用户态）；解析可模糊测试；AI 上下文继续不可信标记 + schema 整条作废。

4\. 默认关：`\[detect.l7]` / `\[detect.rules]` / `\[detect.ebpf]`（及 XDP）默认 off；无权限则降级并留痕。

5\. Windows 数据面主路径 = \*\*WFP\*\*；eBPF-for-windows = \*\*实验轨\*\*，非 0.5.0 阻塞项（见 NGFW\_EVOLUTION「Windows 数据面决策」）。



建议节奏：在 0.4 完成后约 \*\*6～10 周\*\*（是否自研 WFP callout、eBPF 深度影响上限）。



| 发版建议 | 内容范围 |

|----------|----------|

| \*\*0.5.0\*\* | Batch E + F + H（P0）：解析复用、规则子集、Win/Linux 用户态可跑、默认关、可观测 |

| \*\*0.5.1\*\* | Batch G（P1）：Linux eBPF 流表 + XDP map 联动、降级与 reconcile |

| \*\*0.5.2\*\* | stretch：AF\_XDP 深检、JA4 完善、WFP callout 感知、eBPF-for-windows 实验文档包 |

\## 7. 明确不在 0.5 范围（Won't）



| 项目 | 归属/原因 |

|------|-----------|

| 协调者选举、N-of-M \*\*情报升格\*\*、STIX/MISP | \*\*0.6\*\* |

| 100% Suricata/ET 兼容、LUA、文件还原、TLS 解密 | 范围爆炸 |

| 规则自动从公网更新 | 供应链与稳定性 |

| 默认启用 XDP/全量规则 | 违背默认安全 |

| eBPF-for-windows 为 Windows 必选数据面 | 已拍板 WFP 主路径 |

| 扩大 `Firewall` trait 为通用 NGFW API | 破坏传感器/执行器分离 |

| 多租户策略控制台、邮件中心 | 非本阶段 |

| 在内核执行 AI 或复杂剧本 | 信任边界错误 |

\## 8. 跨 Batch 通用风险清单



| # | 风险 | 应对要点 |

|---|------|----------|

| 1 | 规则子集范围蠕变 | 先冻结 `RULESET\_SUBSET`；超集拒绝加载 |

| 2 | 规则/指纹证据投毒 AI | 摘要 + 不可信标签 + schema 作废 |

| 3 | 规则引擎直接封禁 | crate 依赖图禁止链 firewall；code review 清单 |

| 4 | XDP 与 nft/COM 双执行混乱 | `via=` 标签；map 只同步已批准集；TTL reconcile |

| 5 | 内网写入高速 drop 表 | 写入前硬过滤；负路径测试 |

| 6 | 性能：full 捕获 + 全规则 | 默认 control；规则默认 off；窗口与规则数上限 |

| 7 | pcre/内容匹配 DoS | 时间与大小预算；失败记 metrics 不崩溃 |

| 8 | Windows/Linux 行为「假一致」 | 同一测试向量；文档写明能力差 |

| 9 | 驱动签名拖死发布 | 0.5.0 不依赖新 callout；WinDivert 策略沿用 0.4 |

| 10 | 用户误开 XDP 导致业务中断 | 默认 off；开启需显式确认；一键关闭 |

\## 9. 配置草案（文档用，非最终 TOML）



```toml

\[detect.l7]

enabled = false

ja3 = true

\# ja4 = false



\[detect.rules]

enabled = false

path = ""                 # 本地规则包路径；空则不加载

auto\_block = false        # 即使命中也不自动封，除非显式 true 且过白名单策略

max\_rules = 5000



\# Linux only；Windows 忽略或报不支持

\[detect.ebpf]

enabled = false

xdp\_drop = false          # true 时才把批准集合写入 XDP map
