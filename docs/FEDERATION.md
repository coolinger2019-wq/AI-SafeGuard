# 组织协同（Federation）

> 0.6 F100 协议层落地版。设计原则与批次规划见 [ROADMAP-0.6.md](ROADMAP-0.6.md)；
> 0.4 传输与身份层的设计沿革见 [NGFW_EVOLUTION.md](NGFW_EVOLUTION.md) §6。

## 一、组织是什么：一张 CA 证书，不是一个名字

组织的身份 = 组织 CA（"公章"）。**谁持有本组织签发的节点证书，谁就是组织成员**；
组织名只是公章上刻的字（证书 CN，展示用），不是加入凭据——名字谁都能打，证书伪造不了。

创建与加入流程（管理员操作，命令行）：

```bash
# ① 协调者机器：创建组织（生成 CA，组织名可选，默认 AI-SafeGuard Organization CA）
aisafeguard fed init-ca [组织名]

# ② 给每台要加入的机器发"工牌"（证书 + 私钥，人工分发到目标机器）
aisafeguard fed issue-cert <节点名> [--san <dns|ip> ...]

# ③（推荐）预登记指纹：关闭该节点的 TOFU 抢注窗口
aisafeguard fed expect <节点名> <指纹>

# ④ 目标机器 config.toml：
#   [fed]
#   enabled = true
#   role = "agent"
#   node = "<节点名>"
#   coordinator = "https://<协调者地址>:7421"
#   （证书放 <数据目录>/fed/ 默认位置，或用 ca_path/cert_path/key_path 指定）
```

节点启动后自动入伙。没有本组织证书的机器，输什么名字都进不来（mTLS 拒连）。
成员名册：`GET /fed/members`（节点名 / 证书指纹 / 最后在线）；驱离用
`fed revoke <节点名|指纹>`（立即拒连）；换证书 = 先 `fed expect` 登记新指纹。

## 二、线上协议 v1（F100 冻结）

所有 `/fed` 请求（hello / events / proposals）共用一个 JSON 信封：

```json
{
  "proto": "1.0",              // major.minor
  "node": "agent-1",           // 节点名（证书绑定）
  "seq": 42,                   // 节点本地单调序列号，重连不清零（持久化）
  "ts": 1759200000,            // 发送方时钟（秒）
  "type": "hello|events|proposals",
  "payload": { },              // 各消息类型的 schema
  "sig": "<hex>"               // 节点证书私钥对整条消息的 ECDSA P-256 签名
}
```

- **版本协商**：major 不同 → 拒连（HTTP 426 + 双方版本号，GUI 告警）。
  minor 差异 = 未知字段忽略（serde 默认行为，双向写死的向前兼容规则）。
  **升级顺序：先升级协调者（minor 兼容旧节点），再逐台升级节点。**
- **幂等与去重**：消息 ID = `node:seq`。接收方 24h 窗内 seen 集合去重；
  seq ≤ 已见最大值且不在 seen 集合 = 序列号回退（备份恢复/伪造重放）→ 拒收 + 告警。
- **防重放**：信封 ts 偏离接收方时钟 > 24h 拒收。事件 payload 同受 24h 补传窗约束
  （超窗事件不再外发——本地哈希链是事件完整性的真源，外发本来就是副本）。
- **防抵赖**：mTLS 只保连接，`sig` 跟着消息走——协调者留存的原始消息可离线验签
  （验签公钥取自对端 mTLS 证书）。签名覆盖信封全部字段（含 payload）。
- **畸形消息**：单条丢弃 + 计数（hello 响应的 stats 可见），不断连、不刷 GUI 事件、
  不 panic（模糊测试护栏覆盖解析层）。
- **失败语义（agent 侧）**：网络失败 → 同一信封原样重发（接收方去重保证幂等）；
  被 4xx 拒收 → 丢弃信封下轮重建（游标未推进，不丢数据）；hello 426 → 版本失配
  阻断，只发 hello 探测，直到协调者接受。

## 三、多机印证引擎（F200，已落地）

组织核心价值：**多台机器看到同一个攻击者 = 组织比我单个人更确信**。协调者在内存
滑动窗里聚合各节点观测（默认 10 分钟窗、≥2 个独立节点），达成即产出组织印证事件：

| 维度 | 攻击者键 | 说明 |
|---|---|---|
| `ip` | 源 IP | 同一 IP 被多节点独立观测 |
| `fingerprint` | JA3 / JA4 | 同一 TLS 指纹跨节点 |
| `credential` | 用户名 | 同一用户名在多节点蜜罐被投递（argon2id 随机盐使哈希跨节点不可比——**v1 按用户名比对**，任何可逆/口令材料不出节点） |
| `canary` | 源 IP | 蜜饵水印跨节点触发 = 横向移动线索，最高严重度 |

- **印证只加置信**：组织事件经 `GET /fed/org-feed`（游标拉取）到达各节点，本地
  复验（本节点是否观测过该源/指纹/用户名）命中才提示，未命中留痕——处置永远
  归节点本地决策，永不全网下发。
- **独立性**：单节点重复上报永不触发；协调者可离线验签每条原始信封。
- **时钟降权**：节点经 hello 对表上报偏移，|偏移| > 5s 的观测不参与印证。
- **协调者无状态**（拍板决议②）：节点事件不进协调者事件库——观测只在内存窗口
  （重启丢窗 = 降级本地模式），原始签名信封进有界审计日志 `<数据目录>/fed/audit.jsonl`
  （10MB 轮转一代，`fed audit` 导出尾部）。

## 三点五、组织建议闭环（F300，已落地）

- **产生**：两个来源——印证引擎（ip/canary 维度达成印证时附带产出组织建议）与
  节点 AI 建议组织共享（协调者收到后重广播全组织）。
- **接收**：各节点经 org-feed 拉取后**四关本地复验**（IP 合法、非内网保护、本节点
  近期有该源活动、未被本地误报抑制），全过 → 进慢路径 pending（人工确认，灰度
  TTL 与本地建议同一套 apply 流）；任一关失败 → 静默丢弃 + 日志留痕。
- **回流与升级**：建议落定（采纳/收弃）后节点回报协调者（按 (节点,引用) 去重）；
  采纳率 ≥ `[fed].org_adoption_percent`（默认 60%）且**零误报**且采纳 ≥2 节点 →
  升级「组织推荐」广播全组织，后续该键建议推送时默认严重度提高——**仍是建议**。
- **误报广播**：`[fed].share_fp`（默认关）开启后，本地误报标记以建议性质广播，
  他节点规则行提示「组织内 N 节点标记误报」，跟进与否全由本节点人工决定。
- **来源位**：组织建议应用的规则 origin=org（来源「组织协同」、灰度语义与 AI
  建议一致）；`/api/status` 新增 org_metrics（建议采纳率、印证命中率口径）。

## 三点七、韧性（F400，已落地）

- **分区降级**：协调者失联 → 节点只记警告、本地检测/防火墙照常（0.5 行为不变）；
  恢复后按游标补传，协调者按（节点，序列号）去重——断链期不重不丢。
- **风暴抑制**：协调者对单节点入站限频（`[fed].inbound_rate_per_min` 默认 240/分钟，
  0 = 不限），超限降级「仅心跳」5 分钟自动恢复；出站侧结构性限频（每周期单批
  上限、建议按游标幂等、印证广播按攻击者键冷却）。
- **软隔离**（与吊销的区别：吊销断一切连接 = 驱离，隔离 = 留观察的停权）：
  ```bash
  aisafeguard fed quarantine <node> [原因]              # 隔离：保留心跳与审计
  aisafeguard fed quarantine <node> --lift <指纹前缀>   # 解除：需 ≥16 位指纹确认
  ```
  隔离期消息仍进审计日志（可离线验签取证）；隔离/解除动作经 org-feed 广播全组织。
- **有界队列**：出站积压超 10k 按「丢新留旧」牺牲最新段（计数告警）——事件完整性
  以本地哈希链为准，外发本来就是副本。

## 三点八、STIX 2.1 情报交换（F310，已落地）

```bash
# 导出（协调者或任意节点）：四类对象 + 节点证书签名
aisafeguard fed audit stix包.json --format stix
# 导入（须先取得签发方成员证书放入 <数据目录>/fed/certs/<节点>.pem）
aisafeguard stix-import stix包.json
```

- **导出**：`identity`（节点）/ `indicator`（IP/域名/JA3/JA4，内网地址与
  fed:/stix: 回灌源不导出）/ `observed-data`（蜜罐交互摘要含 SCO）/
  `sighting`（印证命中，只挂能映射到的 indicator）。**凭证永不导出**（红线有
  自动化断言）。包 = bundle + 节点证书 ECDSA 签名，篡改即拒收。
- **导入**：验签失败/缺签名/超 5MB/超条数一律拒收；IOC 进情报表
  （`stix:<节点>` 源），**默认只告警**——命中来源在事件流打 `ioc-hit` 标签
  （约 1 分钟内生效），防火墙无自动动作；`valid_until` 到期自动失效（缺省 7 天）。
- **外部验证**：`cargo test -p aisafeguard-app write_sample_for_external_validation
  -- --nocapture` 生成 `target/stix-sample.json`，然后
  `python -c "import json,stix2; stix2.parse(json.dumps(json.load(open('target/stix-sample.json'))['bundle']))"`
  （python-stix2 3.0.2 实测通过）。
