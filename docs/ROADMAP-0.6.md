# ROADMAP-0.6:多机协同完全体(Federation GA)

> 定位:0.5.x「单机地基」收官之后的第一个组织级版本。0.5 回答「一台机器上谁碰了我、我该封谁」;0.6 回答「多台机器看到同一个攻击者时,组织比我单个人更确信」。
> 动机(README 已留白):多机印证 / 选举 / STIX / 「组织」来源位,留给 0.6,不在 0.5 批实现。0.5.4-0.5.6 收口的「干净事件 + 可解释封禁 + 误报一键闭环」是印证引擎的输入;0.4 落地的 fed 基建(mTLS/CA/预登记/吊销/quorum 雏形/事件上报/情报同步/建议推送)是传输与身份层。
> 总目标:**让 N 台机器的事件产生 1 + 1 > 2 的确信度,同时保持节点自治——跨节点只同步建议与证据,永不直接下发处置命令**(0.5 架构红线,0.6 不变)。
> 参考对象:HFish 的 server/node 星型拓扑与节点单向出连(学产品形态),MISP 的共享社区模型(学「共享的是观测不是判决」),不学它们的集中式强管控。
> 编号约定:任务号 `Fxxx`。若 0.5.7-0.5.9 批次已有占位编号,本文档顺延,任务号不变。

## 0.6 第一性设计决定(先于任何任务,全批次约束)

1. **协调者无状态**:协调者只做身份(CA/证书)、消息中转与印证聚合,**不持久化节点事件**。事件与哈希链永远在各节点本地(现有审计模型的延伸)。这一条杀死 90% 的单点与隐私问题。
2. **节点自治,建议而非命令**:印证结果、组织建议、误报标记,全部以「建议 + 本地复验」到达节点;节点复验(本节点是否观测到该源、内网保护、抑制列表)后自行决定。复验失败静默丢弃 + 留痕。
3. **简单可解释的故障模式**:分区/脑裂时节点降级为纯本地模式(0.5 行为),恢复后补传;**不做 raft/多活/强一致存储**——单人 vibe coding 项目,一致性模型必须能用一张图画明白。
4. **印证只加置信,不加处置**:多节点看到同一攻击者 = 严重度与 TTL 建议升级,不自动触发全网封禁(内网保护与「AI 不自动处置」红线不变)。

## 第一批:协议与身份

### F100 fed 协议 v1 冻结 — 规模 M

**背景**:现有 fed 有事件上报、情报同步、建议推送,但没有协议版本概念。0.6 要新增印证广播、组织建议、误报标记等消息类型,必须先冻结线上格式,否则 0.6.x 每次加消息都是破坏性变更。

**范围(In)**
- 定义 fed wire protocol v1:消息类型枚举(event / intel / suggestion / corroboration / fp-flag / heartbeat / ...)、每类 schema、签名覆盖范围(整条消息 + 节点证书签名,对齐现有 mTLS 但消息级留防抵赖)。
- 版本协商:`major.minor` 握手;major 不兼容 → 拒连 + GUI 告警;minor 新字段忽略策略(向前兼容规则写死)。
- 幂等与去重:每消息带全局唯一 ID(节点 ID + 本地单调序列号),接收方按 ID 去重(TTL 内的已见集合)。
- 旧节点策略显式化:major 不匹配拒绝连接,文档写明,不静默降级。

**红线 / 负路径**
- 任何消息解析失败 → 单条丢弃 + 计数告警,不断连不 panic(对齐现有模糊测试护栏);畸形消息风暴触发该节点速率限制(F400)。
- 协商失败原因必须可诊断(GUI 与日志给出双方版本号)。

**验收**
- [x] 双实例互连:版本一致正常;一方 major 升级 → 拒连且双方日志/界面可见原因。(单元级:version_compatible 矩阵 + agent 426 阻断/恢复;双实机互连归 F600 集群 e2e)
- [x] 同一条消息重发(模拟补传) → 只处理一次,事件不重复。(单元级:DedupSet 窗口/容量 + check_fed_seq 回退拒收;补传 24h 窗实测归 F600)
- [x] fuzz 随机消息打 fed 端口:无 panic,异常计数可见。(确定性伪随机 2000 轮解析/规范化 fuzz 测试;计数经 hello stats 暴露;打真实端口的 e2e 归 F600)

> **F100 状态(0.5.12)**:已实现——信封(proto/node/seq/ts/type/payload/sig)、版本协商(major 拒连 426 + 双方版本号)、消息级 ECDSA P-256 签名(节点证书钥,验签公钥取自 mTLS 对端证书)、node+seq 幂等(24h seen 集合 + 持久化高水位,回退拒收)、hello 心跳兼 last_seen、±1h 时钟窗改 24h 补传窗、agent 同信封重发/4xx 重建/401 材料重建。新增 fedproto.rs 协议模块与 docs/FEDERATION.md;`fed init-ca` 支持组织名(展示用 CN)。依赖净增:ring、x509-parser(均在既有依赖树内)。

### F110 协调者主备与租约 — 规模 M

**背景**:现协调者是单点——它死了组织不等于死(节点自治),但证书签发、新节点加入、印证聚合会停。做「有限高可用」,不做共识。

**范围(In)**
- active-standby 主备:管理员签发第二协调者证书,备用通过心跳租约(lease,默认 10s 可配)感知主存活;主失联超租约 → 备提升(可配自动/手动,**默认手动**,自动提升需 quorum 同意)。
- 成员侧「当前协调者」发现:多点候选时按「预登记优先 + quorum 票数」仲裁;仲裁失败 → 节点保持纯本地模式并告警,不猜。
- 主恢复:发现自己的租约已被接管 → 自动降级为 standby,事件序列对齐(备转主期间的签发记录经审计日志合并,冲突 = 后签发者拒绝 + 告警)。
- 所有切换动作写审计日志(fed audit 导出覆盖)。

**范围(Out)**:不做多活;不做数据复制(协调者无状态,见第一性决定 #1);不做自动故障转移的脑裂双写(默认手动切换就是为了避免)。

**红线 / 负路径**
- 双主期窗口(自动模式)内,签发请求由 quorum 裁决唯一受理方;裁决失败两个都拒——宁停勿乱。
- 时钟回拨/租约异常 → 保守降级,不允许「以为自己还是主」继续签发。

**验收**
- [ ] kill 主协调者 → 节点 N 秒内标记协调者失联、进入本地模式(现有降级行为),日志可解释。
- [ ] 手动提升备 → 成员重新收敛;期间各节点本地检测不停摆(回归 0.5 行为)。
- [ ] 双活注入(网络分区两半各认为主存活)→ quorum 拒绝签发,审计日志完整。

## 第二批:印证引擎

### F200 多机印证引擎(0.6 核心)— 规模 L

**背景**:单节点说「192.0.2.1 在扫我」可信度一般;三个节点在 10 分钟内独立说「同一个 IP + 同一 JA3 指纹在扫我们」,这就是组织级证据。印证是把 0.5.x 收口的干净事件变成组织确信度的引擎,也是 AI 慢路径跨节点证据链的来源。

**范围(In)**
- 印证维度(v1 四个,全部可配开关与阈值):
  1. **源 IP 跨节点**:同一 IP 在时间窗(默认 10min)内被 ≥K 个节点(默认 2)各自观测到 → `ip_corroborated`;
  2. **指纹跨节点**:同 JA3/JA4(或规则命中 ID)跨 ≥2 节点 → `fingerprint_corroborated`;
  3. **凭证跨节点**:同一用户名/口令哈希对出现在 ≥2 节点的蜜罐 → `credential_corroborated`(直接复用 0.5.9 凭证库哈希,明文不出节点);
  4. **蜜饵联动**:同一源触发 ≥2 节点的 canary 水印(或 1 节点水印 + 1 节点凭证)→ `lateral_suspected`(横向移动线索,最高严重度)。
- 印证结果作为组织事件(coord 聚合)广播;各节点收到后**本地复验**(本节点是否有该源活动记录)再决定升级本地严重度/延长 TTL 建议/推 AI 慢路径。
- 事件去重:同一攻击者在同一窗口内只产一次组织印证事件(滑动窗口 + 攻击者键 = IP|指纹|凭证的复合键)。
- 离线补传:节点重连后按重放窗口(F320 序列号)补传缺失事件,印证引擎按事件原始时间戳(带时钟偏移容错)计算窗口。

**范围(Out)**:不做跨节点流关联(如 TCP 会话拼接);不做 ML 聚类——规则化维度足够且可解释;不做跨组织印证(留 0.7)。

**红线 / 负路径**
- 凭证只以 argon2id 哈希参与比对,任何印证消息不携带口令明文与可逆材料(自动化断言)。
- 印证只加置信:本地快路径升级采纳是**建议**,受内网保护、抑制列表、quorum 策略约束;默认仍需人工确认(自动采纳是显式开关,延续 0.5 哲学)。
- 攻击者控制一个节点伪造「多节点都看到了 X」→ 单节点声明无效,印证必须有 ≥K 个**独立节点**的本地观测记录,协调者只聚合原始上报(每条附节点签名,可事后审计验签)。

**验收**
- [ ] 3 实例集群:IP 依次打两个节点 → 组织印证事件出现,指纹/凭证维度各有一次实测。
- [ ] 伪造单节点重复上报同一 IP → 不触发印证(独立性校验实测)。
- [ ] 印证事件在 GUI 可展开证据链(哪些节点、各自事件、时间线)。

### F320 时钟、序列号与重放防护 — 规模 S

**背景**:跨节点时间窗对齐是印证正确性的地基,也是最容易翻车的地方。单独收口,不埋在 F200 里。

**范围(In)**
- 节点 ID + 本地单调序列号进每条事件(发布者保证单调,重连不清零——持久化 last-seq)。
- 启动 NTP/系统时钟健全性检查:偏移 > 阈值(默认 5s)启动告警;运行周期复测,偏移超窗 → 该节点事件在印证计算中降权并告警。
- 重放防护:重放窗口(默认 24h)外的补传事件不进入印证,仅归档;窗口内的按序列号去重。
- 印证窗口计算用「节点原始时间戳 ± 偏移容差」,不信任任一节点的时钟。

**验收**
- [ ] 时钟偏移注入(改 30s)→ 告警 + 降权实测;NTP 恢复后自动解除。
- [ ] 重放旧事件(>24h)不触发新印证。
- [ ] 序列号回退(节点从备份恢复旧数据)检测并拒绝,审计留痕。

## 第三批:组织闭环

### F300 组织建议闭环 + 「组织」来源位 — 规模 L

**背景**:0.4 已有「建议推送(本地复验、仅慢路径)」,0.6 把它扩展成完整组织闭环:印证引擎、任一节点 AI 慢路径、误报标记,三种来源的组织级建议,全组织复验、回流统计、形成采纳率指标。

**范围(In)**
- **org-suggestion 生命周期**:产生(印证引擎规则产出 / 节点 AI 建议标记为组织共享)→ 推送全组织 → 各节点本地复验(本节点观测?内网?抑制?)→ 采纳(灰度 TTL)→ 转正 / 收弃 → 结果回流协调者统计。
- **quorum 升级**:采纳率 ≥ X%(默认 60%,可配)且零误报标记 → 升级为「组织推荐」,对后续加入复验的节点提高默认严重度(仍是建议)。
- **「组织」来源位落地**:防火墙规则来源枚举新增 `org-corroborated` / `org-suggestion`;GUI 与 `GET /api/rules` 展示组织来源一句话原因与 TTL 文案,可跳转组织印证事件;价值指标增加组织建议采纳率、印证命中率。
- **误报广播**:A 节点一键误报闭环后,组织内广播 fp-flag(建议性质)→ 其他节点 GUI 在相关事件/规则行提示「组织内 N 节点标记误报」,由本节点人工决定是否跟进(不强制解除——节点自治)。
- **抑制列表组织共享**:抑制条目可标记组织共享(默认不共享),共享后其他节点收到提示,人工确认后生效。

**范围(Out)**:不做组织级统一策略下发(如协调者规定全网 auto_block)——那是 NGFW/EDR 的产品方向,README「不适合谁」已排除;不做跨组织建议交换(0.7)。

**红线 / 负路径**
- 永不直接下发封禁命令;org-suggestion 复验失败静默丢弃 + 计数。
- 建议风暴:同一来源每窗口限频(F400 统一实现);回流统计按消息 ID 幂等。
- 误报广播不允许解除他节点手动规则(对齐 0.5 误报闭环约束)。

**验收**
- [ ] 端到端:节点 A AI 建议标记组织共享 → 节点 B 收到 → 复验采纳(灰度 TTL)→ 回流 → 双方 GUI 状态一致;B 无该源活动 → 静默丢弃留痕。
- [ ] quorum 升级路径实测(X% 达成与未达成两分支)。
- [ ] 误报广播:节点间提示出现,跟进与不跟进都留痕。
- [ ] 组织来源规则在 `/api/rules` 与 GUI 可解释、可跳转证据。

### F310 情报:STIX 2.1 导入导出与 IOC 消费 — 规模 M

**背景**:README 留白「STIX 给 0.6」。组织级情报的价值不在收集在共享:节点产出的 IP/指纹/凭证哈希/蜜饵命中,组织内标准化交换;外部 IOC 清单导入本地命中。

**范围(In)**
- **导出**:STIX 2.1 包——`indicator`(IP/CIDR、JA3/JA4、域名)、`observed-data`(蜜罐交互摘要)、`sighting`(印证事件,对应哪个 indicator 被哪些节点看到)、`identity`(节点)。fed audit 增加 `--format stix`。凭证**不导出**(只导出「某凭证对在 N 节点出现」的计数指标,不含哈希本身——哈希也只留在组织内)。
- **导入**:组织内共享清单(节点手工导入或经 fed 推送):IOC 本地命中检测 → 事件打 `ioc-hit` 标签,只告警;命中威胁情报(现有快路径情报位)联动可配。
- 清单治理:来源标识、导入时间、valid_until → 到期自动失效(对齐现有 TTL 哲学);导入文件大小与条数上限。

**范围(Out)**:TAXII 服务器/客户端(太重,明确不做);STIX 完整对象模型(实现 Indicator/ObservedData/Sighting/Identity 四类,v1 够用)。

**红线 / 负路径**
- 导入清单默认**只告警不自动封**;恶意清单投毒(超大声宣称 8.8.8.8 是 C2)被限频 + 人工审核入口。
- 导出包签名(HMAC + 可选节点证书),接收方验签失败拒收;内容脱敏检查自动化断言(无明文口令、无内网拓扑细节如节点内网 IP 以外的信息)。

**验收**
- [ ] `fed audit --format stix` 产出可被现成 STIX 解析库(如 python-stix2)验证的包。
- [ ] 导入含已知扫描源清单 → 该源来访打 `ioc-hit` 标签,防火墙无自动动作(默认)。
- [ ] 到期 IOC 自动失效实测;伪造签名包拒收实测。

## 第四批:韧性

### F400 分区容忍、风暴抑制与被攻陷节点隔离 — 规模 M

**背景**:多机系统真正的风险不在功能在滥用面:一个节点被攻陷/被控后,可以把组织当广播放大器。这批是 0.6 的「负路径工程」,对齐你 NEGATIVE-PATH-TESTING 的传统。

**范围(In)**
- **分区降级**:协调者失联 → 节点纯本地模式(回归 0.5 行为);网络对半分 → 双方各自本地模式,恢复后按序列号增量补传 + 去重。
- **风暴抑制**:每节点出站消息按类型限频(事件 N/s、建议每源每窗口一次、印证广播每攻击者键一次);协调者对单节点入站限频,超限降级为「仅心跳」(隔离观察)。
- **软隔离**:管理员一键将节点置 `quarantined`:保留心跳与审计通道,断其事件/建议广播;隔离动作本身广播并留痕;解除需管理员 + 指纹确认。与吊销的区别:吊销断一切(驱离),隔离是留观察的停权。
- **有界队列**:协同发送队列有界(默认 10k 条),写满策略显式文档化(建议:丢新留旧 + 计数告警,事件完整性以本地哈希链为准,外发本来就是副本)。

**红线**:任何抑制/隔离动作不得影响节点本地检测与防火墙兜底(本地自治优先于协同)。

**验收**
- [ ] 分区注入(toxiproxy 或 netns/iptables 断链)→ 双半各保本地能力,恢复后无重复无丢失。
- [ ] 单节点洪泛伪造事件 → 被限频,其他节点收到的事件量有上限,隔离一键生效。
- [ ] 隔离中节点本地检测正常(回归)。

## 第五批:体验

### F500 GUI 多节点面板 — 规模 M

**范围(In)**
- 仪表盘新增「组织」页:节点列表(名称/在线状态/版本/时钟偏移/隔离状态/近期事件数)、组织事件流(印证事件、组织建议、fp-flag,可筛选)、当前协调者与主备状态。
- 节点详情视图:单节点近期事件、组织建议采纳状态、抑制列表;操作入口:软隔离、邀请广播抑制、org-suggestion 审批。
- 印证证据链视图:攻击者键 → 命中节点时间线 → 各节点原始事件跳转。
- 面板数据通路:经协调者转发(无状态代理)或本地缓存轮询;**面板只读,不写节点数据库**(架构红线)。

**红线**:面板操作全部走现有建议/隔离通路,不在 GUI 层新开命令通道;离线节点展示最近已知状态 + 「数据截至」时间戳。

**验收**
- [ ] 三节点演示:断一个节点,面板 1 个心跳周期内反映;隔离操作两处入口(面板/CLI)等价。
- [ ] 证据链视图从组织事件跳得到任一节点本地事件详情。

## 跨任务红线汇总(全批次适用)

1. **协调者无状态、节点自治、建议而非命令**——0.6 第一性决定,任何任务不得以便利为由违反。
2. 新协同能力默认关/默认保守:自动采纳、自动提升、自动故障转移,全部显式开关 + 默认人工。
3. 内网/回环永不自动封;组织建议同受内网保护与抑制列表约束。
4. 凭证与口令材料:跨节点只有 argon2id 哈希(仅组织内)与计数指标(可出组织),永不明文、永不 reversible。
5. 全仓库 `forbid(unsafe_code)` 不变;fed 协议解析器入模糊测试护栏。
6. 单节点故障/被攻陷不降低其他节点的本地检测与防火墙兜底能力(本地自治优先)。

| 风险 | 预案 |

| 选举/一致性做复杂导致 0.6 失控 | F110 已限死 active-standby + 手动默认;若开发中发现仲裁逻辑膨胀,砍为「管理员指定主备,仲裁只留告警」 |

| 单人维护负担 | 每批都可独立发布(0.6.0=F100+F110+F200 最小可用印证);F310/F500 可延至 0.6.1 |
