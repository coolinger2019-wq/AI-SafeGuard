\# AI-SafeGuard 0.4 里程碑任务拆分



> 版本规划草案 · 与 `docs/ROADMAP.md` 配套使用  

> 目标版本：\*\*0.4.x\*\*  

> 原则：可安装、可服务化、配置少重启、封禁可解释、组织协同可吊销可印证、AI 价值可度量。  

> \*\*不做\*\*完整 NGFW / DPI 特征库 / 企业多租户控制台 / 自动更新（可放 0.5）。



\---



\## 0. 目标陈述



\*\*0.4 = 装得上、跑得稳、改配置少重启、封禁粒度可解释、协同更安全、价值可度量。\*\*



威胁模型保持克制：主要面向扫描、暴破、常见自动化攻击与可审计的自动/半自动处置；\*\*不宣称\*\*对抗国家级 APT。



设计约束（沿用既有架构）：



1\. 传感器与执行器分离：防火墙 trait 保持窄口，检测能力经事件总线接入。

2\. 跨节点共享\*\*建议\*\*而非命令；接收端本地复验后执行。

3\. 自身安全优先：`#!\[forbid(unsafe\_code)]`、AI 建议 schema 整条作废、内网/回环永不自动封。

4\. 外发通道只读事件总线，失败不反哺引擎（禁止自反馈风暴）。



建议节奏：单人全职约 \*\*4～6 周\*\*；按 Batch 可独立发版。



| 发版建议 | 内容范围 |

|----------|----------|

| \*\*0.3.7\*\* | Batch A 子集（热更新 + 服务/权限文档 + 需重启项标注） |

| \*\*0.4.0\*\* | Batch A 完成 + Batch B 核心 |

| \*\*0.4.1\*\* | Batch C（吊销 + quorum 与降级） |

| \*\*0.4.2\*\* | Batch D（GitHub、演示、README）；可与 0.4.0 并行 |

\## 1. Batch A：装得上、跑得稳



\*\*周期建议：\*\* 1～1.5 周  

\*\*出口标准：\*\* 新人按文档约 10 分钟在 Windows / Linux 各起一个实例：蜜罐可触发、封禁可下发、syslog 可接收。



| ID | 任务 | 优先级 | 验收标准 | 潜在坑与应对 |

|----|------|--------|----------|----------------|

| A1 | Windows 服务安装体验收口 | P0 | `service install` 一次成功；开机自启；非管理员 GUI 可经本地 API 查看数据 | \*\*坑：\*\* 服务账户与用户凭据管理器隔离，服务读不到用户存的 AI Key。\*\*应对：\*\* 服务使用 `ProgramData` 或服务专用凭据槽；文档写清「服务模式 vs 交互模式」密钥路径差异。 |

| A2 | Linux systemd unit + 最小权限 | P0 | 提供 `aisafeguard.service`；文档写清 `CAP\_NET\_RAW`；无捕获场景可无 CAP；`headless` 稳定运行 | \*\*坑：\*\* 用户长期以 root 运行忘记收权。\*\*应对：\*\* unit 使用 `AmbientCapabilities=` + `NoNewPrivileges=`；文档提供「仅蜜罐+频次、不开捕获」配置。 |

| A3 | WinDivert 交付说明与校验 | P0 | 缺 `.sys` 时明确提示官方获取渠道；可选启动哈希校验；不静默失败 | \*\*坑：\*\* 非官方驱动带来供应链风险。\*\*应对：\*\* 只链官方说明；发布页给出期望 SHA-256；校验可配置开关。 |

| A4 | 配置热更新（第一批） | P0 | `\[detect]` 阈值、`\[syslog]`、`\[notify]`、`\[ai].enabled` / `auto\_apply`、暴露面扫描间隔\*\*无需重启\*\*生效 | \*\*坑：\*\* 热更与运行中任务竞态（双重订阅、旧任务未退出）。\*\*应对：\*\* 每通道 `watch` / `CancellationToken`；先停旧再启新；单测覆盖连续变更。 |

| A5 | 需重启项在 UI 明确标注 | P1 | 蜜罐端口、API 绑定、捕获开关等标注「需重启」；保存后 toast；状态页可显示「生效配置 vs 文件配置」差异 | \*\*坑：\*\* 用户以为已生效，夜间蜜罐端口未变更。\*\*应对：\*\* 状态页 diff + 醒目提示。 |



\### Batch A 完成定义（DoD）



\- \[ ] Windows 服务与 Linux systemd 文档可独立照做成功

\- \[ ] 热更新项有单测或集成测试，连续改配置无泄漏任务

\- \[ ] 需重启项在 GUI/文档双处可见

\- \[ ] 缺 WinDivert / 无 CAP 时优雅降级，日志可读

\## 2. Batch B：封禁可解释 + 误报闭环



\*\*周期建议：\*\* 1～1.5 周  

\*\*出口标准：\*\* 能说清「为什么封、封多久、是否误报、AI 是否有用」，而不只是 IP 黑名单列表。



| ID | 任务 | 优先级 | 验收标准 | 潜在坑与应对 |

|----|------|--------|----------|----------------|

| B1 | 规则模型扩展：`ip` → `ip + optional port + optional tag` | P0 | 防火墙 trait 支持可选端口；旧「仅 IP」规则完全兼容；审计记录粒度 | \*\*坑：\*\* Windows 规则数量膨胀；nftables 集合语义与 Win 不一致。\*\*应对：\*\* 端口级规则独立命名前缀；每来源规则数上限，超限合并为 IP 级并写审计。 |

| B2 | 轻量 L7 标签（非完整 DPI） | P1 | HTTP 蜜罐/捕获可记录 method、path 前缀、可疑 UA 类标签；标签进入事件与 AI 上下文 | \*\*坑：\*\* 半包/异常编码导致 panic 或误标。\*\*应对：\*\* 解析失败只打 `parse\_error`；模糊测试；禁止 unsafe。 |

| B3 | 误报抑制时长可配置 | P0 | `fp\_suppress\_secs` 可配；API/GUI 可查询、清除抑制 | \*\*坑：\*\* 抑制过长导致真攻击漏过。\*\*应对：\*\* 默认 7～14 天；可配置「高严重度忽略抑制」。 |

| B4 | 误报可选 port / protocol 粒度 | P1 | 反馈可带端口；自动封禁匹配支持更细粒度 | \*\*坑：\*\* 过细导致表膨胀、匹配变慢。\*\*应对：\*\* 默认仍按 IP；port 可选；过期反馈定期清理。 |

| B5 | 价值指标仪表 | P0 | GUI 与 `GET /api/status` 暴露近 24h / 7d：建议数、采纳数、误报数、自动封禁数 | \*\*坑：\*\* 指标定义不一致。\*\*应对：\*\* 写死定义——采纳率 = `applied / proposed`，误报率 = `fp / applied`；CHANGELOG 与文档同步。 |



\### Batch B 完成定义（DoD）



\- \[ ] 旧规则升级/读取无破坏

\- \[ ] 灰度 TTL / 转正 / 手动永久 在 GUI 文案区分清楚（可带 `ttl\_source`）

\- \[ ] 指标定义有文档与测试断言

\- \[ ] L7 标签失败不影响主检测路径

\## 3. Batch C：组织协同加固



\*\*周期建议：\*\* 1～1.5 周  

\*\*出口标准：\*\* 双节点 mTLS 可跑；吊销生效；冒用节点名/指纹不一致可演示拦截。



| ID | 任务 | 优先级 | 验收标准 | 潜在坑与应对 |

|----|------|--------|----------|----------------|

| C1 | 证书吊销（先手动 CRL 文件即可） | P0 | `fed revoke-cert <fp>`（或等价）；协调者拒绝已吊销客户端证书 | \*\*坑：\*\* 节点时钟不同步导致吊销时间语义混乱。\*\*应对：\*\* 吊销\*\*立即生效\*\*（不依赖 notAfter）；保留 ±1h 时钟窗并告警偏移。 |

| C2 | 换证与首登流程文档化 / 加固 | P0 | 文档：吊销旧证 → 签发新证 → 清理成员指纹 → 重绑；可选预登记 `node + expected\_fp` 或首登管理员批准 | \*\*坑：\*\* TOFU 抢注（持合法证者抢先绑定节点名）。\*\*应对：\*\* 预登记或首登审批；文档标明风险窗口。 |

| C3 | 多节点印证（quorum）后再自动封 | P1 | 配置如 `min\_peers = 2`：≥N 节点报告同类来源才允许 `auto\_block` / `auto\_apply` | \*\*坑：\*\* 节点不足时功能「假死」。\*\*应对：\*\* 单节点部署自动降级为本地策略；GUI 显示当前印证数。 |

| C4 | 协同审计导出 | P1 | 可导出成员列表、建议同步记录、拒绝原因（指纹不符、已吊销等） | \*\*坑：\*\* 导出暴露内网拓扑。\*\*应对：\*\* 默认脱敏；导出需本地 Bearer token。 |

| C5 | fed 监听面绑定建议 | P0 | 文档强烈建议协调者绑内网地址；首次 init 可交互确认；公网监听需显式确认 | \*\*坑：\*\* 默认 `0.0.0.0` 被外网扫描。\*\*应对：\*\* 交互确认 + 暴露面盘点已计入 fed 端口。 |



\### Batch C 完成定义（DoD）



\- \[ ] 无客户端证书 / 吊销证书 / 指纹不一致 三条负路径有实测记录

\- \[ ] 单节点 quorum 降级行为有测试或文档说明

\- \[ ] 换证步骤可被第三方按文档走通

\## 4. Batch D：对外叙事与分发



\*\*周期建议：\*\* 约 3～5 天（可与 A/B 并行）  

\*\*出口标准：\*\* 陌生人 30 秒内理解产品不是「LLM 内容审核」；能按文档完成一次快路径演示。



| ID | 任务 | 优先级 | 验收标准 | 潜在坑与应对 |

|----|------|--------|----------|----------------|

| D1 | GitHub mirror + CI 产物 | P0 | tag 触发构建 Windows / Linux artifact | \*\*坑：\*\* Gitee / GitHub 双远程不同步。\*\*应对：\*\* 明确主远程；CI 只信任 tag。 |

| D2 | README 重写 | P0 | 副标题强调「主机入侵检测与处置」；开篇否定与 LLM Guardrail 的混淆 | \*\*坑：\*\* 名称仍易被搜偏。\*\*应对：\*\* 固定副标题；英文可加 Host/Endpoint 限定。 |

| D3 | 5 分钟演示脚本 | P1 | 如 `scripts/demo-attack.sh`：触发蜜罐 → detection → 可选 AI 建议 | \*\*坑：\*\* 演示强依赖外网 LLM。\*\*应对：\*\* 提供「无 AI、仅快路径」模式。 |

| D4 | 威胁模型一页纸 | P1 | `SECURITY.md` 或 `docs/THREAT\_MODEL.md`：信任边界、fed 面、捕获隐私、非目标 | \*\*坑：\*\* 过度承诺安全能力。\*\*应对：\*\* 明确非目标列表。 |

\## 5. 明确不在 0.4 范围（Won't）



| 项目 | 原因 |

|------|------|

| 完整 DPI / IPS 特征库 | 资源与定位偏离；易摊薄主线 |

| 邮件通知、复杂报表中心 | 可用 webhook / syslog 替代 |

| 多租户 SaaS 控制面 | 超出主机侧工具边界 |

| 自动更新通道 | 建议 0.5；需签名与供应链设计 |

| macOS 支持 | 无明确用户前不做 |

| 扩大防火墙 trait 为通用 NGFW API | 违反传感器/执行器分离 |

\## 6. 跨 Batch 通用风险清单



建议同步维护于 `docs/LESSONS.md`。



| # | 风险 | 应对要点 |

|---|------|----------|

| 1 | AI 建议投毒（蜜罐 payload 诱导「封全网」） | schema 整条作废；恶意 payload 回归测试 |

| 2 | 外发自反馈风暴 | 外发只读总线；失败仅 tracing |

| 3 | 内网 / DNS / 网关误封 | 硬拒绝回环与内网；可配管理网段白名单 |

| 4 | GUI 用户态与服务高权限状态分裂 | 单一执行器（服务）写防火墙；GUI 只调 API |

| 5 | TTL 语义混乱（灰度 / 转正 / 手动） | GUI 固定文案；事件带 `ttl\_source` |

| 6 | full 捕获高流量拖垮 CPU | 默认 control；full 显式开启；流表 cap 与 drop 计数进 status |

| 7 | 合规表述过度 | ISO 等为「对照表」非认证；README 写明 |

| 8 | 配置热更竞态 | CancellationToken；单测连续变更 |

| 9 | fed 公网误暴露 | 默认引导内网绑定；暴露面盘点告警 |

| 10 | 指标定义漂移 | 采纳率/误报率公式写死并测试 |

\## 8. 验收清单（发布 0.4.0 前）
