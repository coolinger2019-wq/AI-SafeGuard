\# AI-SafeGuard 地基版任务拆分（0.6 之前）



> 文档名建议：`docs/ROADMAP-FOUNDATION.md` 或 `docs/ROADMAP-0.5.3.md`  

> 与 `docs/ROADMAP.md` 配套；\*\*不占用 0.6 版本号\*\*（0.6 仍留给多机协同完全体）。  

> 目标版本建议：\*\*0.5.3\*\*（若 workspace 已是 0.5.2）或 \*\*0.5.x-foundation\*\*。  

> 原则：单机先够用——能抓、能看懂、误报不折腾；为以后多台同步留下干净事件与可解释封禁。



\---



\## 0. 目标陈述



\*\*地基版 = 单机体验收口，为多台打底。\*\*



做完之后，应能稳定演示：



1\. 扫一下 / 打开假登录页 → 事件里看得懂「谁、碰了啥」  

2\. 封禁列表上看得懂「谁、为啥封、多久解、谁决定的」  

3\. 点一下「误报」→ 自动解封相关自动规则 + 暂时不再烦你  



\*\*本版不做：\*\*



\- 多机印证 / 选举 / STIX（归 0.6）  

\- 全面中/高交互蜜罐  

\- 把防火墙页做成完整 iptables 管理器  

\- 扩大 `Firewall` trait 为通用 NGFW API  



设计约束（沿用）：



1\. 传感器与执行器分离；封禁仍走窄口 trait  

2\. 蜜罐数据视为不可信输入；展示与送 AI 均截断、清洗  

3\. 内网 / 回环永不自动封  

4\. 外发只读总线，失败不反哺引擎  



建议节奏：约 \*\*2～3 周\*\*（可按 Batch 拆发版）。



| 发版建议 | 内容 |

|----------|------|

| \*\*地基 Batch 1\*\* | 封禁可解释 |

| \*\*地基 Batch 2\*\* | 误报一键闭环体验 |

| \*\*地基 Batch 3\*\* | HTTP 低交互加强 + 事件详情 |

\## 1. 出口标准（怎样算打完地基）



\- \[ ] 防火墙页每条规则可见：目标、原因摘要、来源（手动/检测/AI/情报）、TTL/剩余时间、灰度 vs 已转正  

\- \[ ] 从规则能跳到相关事件（按 IP 过滤即可）  

\- \[ ] 事件页、规则页、AI 建议处均可「标误报」；一键完成抑制 + 解自动封 + 丢 pending 建议  

\- \[ ] 误报/抑制列表可查、可取消  

\- \[ ] HTTP 蜜罐：至少假登录页 + 若干敏感路径诱饵；事件含 method/path/UA 等摘要  

\- \[ ] SSH/Telnet/通用保持低交互，不升级为中交互 Shell  

\- \[ ] README 或演示脚本：5 分钟单机演示（无多机、可不依赖外网 AI）  

\- \[ ] 版本号与 CHANGELOG 写明「地基版 / 0.6 之前」

\## 2. Batch 1：封禁列表可解释（谁 / 为啥 / 多久）



\*\*周期建议：\*\* 3～5 天  

\*\*出口标准：\*\* 打开防火墙页不再像「无名 IP 黑名单」。



| ID | 任务 | 优先级 | 验收标准 | 备注 |

| F1 | 规则展示模型统一 | P0 | GUI 与 `/api/rules`（或 status 扩展）暴露：`reason\_summary`、`source`、`expires\_at`、`ttl\_source`（trial/promote/manual/engine） | 旧规则无字段时给默认文案「来源未知 / 长期」 |

\## 3. Batch 2：误报一键，别折腾



\*\*周期建议：\*\* 3～5 天  

\*\*出口标准：\*\* 用户只理解一个按钮：「这是误报」。



| ID | 任务 | 优先级 | 验收标准 | 备注 |

|----|------|--------|----------|------|

| F6 | 一键三联动复查 | P0 | 标误报 = 写入抑制 + 解除该来源 engine/ai 自动封禁 + 丢弃 pending 建议；手动规则默认不动（或二次确认） | 若 0.3.4 已有，本批补齐入口与文案 |

| F7 | 三处入口 | P0 | 事件行、防火墙规则行、AI 建议行均可触发同一逻辑 | Console 内嵌/远程行为一致 |

| F9 | 抑制列表 | P0 | `GET` 列表 + 取消抑制；GUI「误报/白名单抑制」小节 | 取消后恢复可被自动封 |

| F10 | 操作反馈 | P1 | Toast：已解封 N 条、已丢弃 M 条建议、抑制至某时间 | 失败原因可读 |



\### Batch 2 DoD

\- \[ ] 抑制期外行为恢复可测  

\- \[ ] 文案避免「删除一切规则」等恐吓性歧义

\## 4. Batch 3：HTTP 低交互加强 + 事件更好读



\*\*周期建议：\*\* 5～8 天  

\*\*出口标准：\*\* HTTP 蜜罐明显比「空端口监听」好用；仍不进行中交互。



\### 4.1 交互边界（写死，避免范围膨胀）



| 做 | 不做 |

|----|------|

| 假登录页（GET 表单 + POST 记「有提交」） | 真验证用户、连真实目录 |

| 常见敏感路径诱饵（如 `/admin`、`/wp-login.php`、`/.env`、`/api/login`） | 完整 CMS/假文件系统 |

| 记录 method、path 前缀、Host、UA、状态码、是否含密码字段名 | 默认持久化明文密码体 |

| 响应像真站一点的短 HTML/JSON | 高交互会话、二次跳转迷宫 |

| SSH/Telnet 维持横幅级低交互 | 假 Shell、可执行命令环境 |



\### 4.2 任务表



| ID | 任务 | 优先级 | 验收标准 | 备注 |

|----|------|--------|----------|------|

| F11 | HTTP 路径路由表 | P0 | 可配置或内置一批诱饵路径；未匹配走通用假页 | 配置改动若需重启，GUI 标注 |

| F12 | 假登录页 | P0 | GET 返回简单表单；POST 记 hit + `login\_post=true`（或等价标签），不回真实成功会话 | 密码字段只记「出现过」，默认不落库明文 |

| F13 | 事件字段 | P0 | 事件详情/API 含 http 摘要：method、path、ua、标签（scan\_path / login\_probe 等） | 与 l7 标签对齐则复用，避免两套字段 |

| F14 | 事件 GUI 详情 | P0 | 列表摘要一行；点开看结构化字段；长 body 截断 | 不可信内容等宽/转义展示 |

| F15 | 与检测/AI 衔接 | P1 | 高频撞登录路径可走既有频次或标签进 AI 上下文 | 不新增第三条执行通道 |

| F16 | 模糊/单测 | P0 | 畸形 HTTP 不 panic；摘要长度有上限 | 保持 forbid(unsafe\_code) |



\### Batch 3 DoD



\- \[ ] 浏览器打开蜜罐 HTTP 端口可见假登录或诱饵页  

\- \[ ] 扫描常见路径有对应事件且可读  

\- \[ ] SSH/Telnet 行为与本版前兼容（低交互）  

\- \[ ] 文档写明：低交互加强，非中交互蜜罐
