# ROADMAP-0.7：情报分级 · 舰队实战 · 规则弹药 · AI 调参者

> 定位：0.6「多机协同完全体」收官后，从**架构完备**转向**检测内容与实战验证**。
> 动机（0.6 复盘）：0.4-0.6 的工时绝大部分给了平台（联邦/STIX/GUI/转发），检测本体
> 仍是「频次引擎 + 薄规则 + 蜜罐 + 一份 5 条的 Feodo 名单」；且产品从未被真实攻击者
> 打过——误报率、噪声水平、印证命中率在真实公网环境下全部未知。0.7 回答一个问题：
> **这套架构接上真弹药、放上真战场，到底值多少。**
> 前置：0.6.1 先发（未发布节攒的情报 GUI/状态反馈/webhook 签名重试），0.7 从干净基线开始。
> 编号约定：任务号沿用 F 系列顺延（F700+）。

| 对象 | 结论 |
|---|---|
| **CrowdSec** | **集成对象**：社区威胁名单替代僵死的 Feodo 源（成熟 bouncer 语义 = 拿来即用的「情报→拦截」模式） |

## 0.7 第一性设计决定（先于任何任务，全批次约束）

1. **数据先行**：规则内容与 AI 调参都以舰队实验的真实数据为输入——先有口径再跑，跑完不许往回找补。
2. **源分级 = 信任显式化**：每个情报源自带置信度与自动封禁许可；「换源同等信任」的操作风险就此根除。内网保护/TTL/审计三道全局保险不变。
3. **AI 调参者不破红线**：AI 只「提议」转正/退役/调阈值，人工确认才生效——与封禁建议同一条「建议而非命令」管道；自反馈回路必须有限频与冷却。
4. **规模克制**：不新增 crate、不做 TAXII、不做 FIM、不做全流量 IPS。

## 第一批：情报源分级与 CrowdSec（0.7.0）

### F710 多源模型与信任分级 — 规模 M

**背景**：现有 `[intel]` 是单源（feed_url），且拉回条目一律按「高置信 C2」自动封禁——换源即同等信任，是 0.6 复盘记录的真实操作风险。多源分级是 CrowdSec 接入的前置。

**范围（In）**
- `IntelConfig` 重构：`feed_url/auto_block` 单源字段 → `[[intel.sources]]` 数组（`name/url/confidence/auto_block/ttl_secs/kind`），`enabled/interval_secs` 保留为总开关；**无兼容层**（AGENTS#1：旧字段直接删，config.example 同步，防漂移测试拦）。
- `run_intel_refresh` 遍历源拉取；自动封禁门控改为 `源.auto_block && confidence=="high"`；内网保护/TTL/已封跳过不变。
- value 冲突策略定死：value UNIQUE 下按源优先级（允许 auto_block 的源优先）upsert，替换「后写者胜」的已知边界。
- GUI 情报段：源列表只读展示（名称/条数/是否允许自动封）；编辑仍走 config.toml 一期。

**红线 / 负路径**
- 关闭 auto_block 的源，即使 confidence=high 也**永不**自动封（自动化断言）。
- 内网/回环条目任何源都拒收（现状保持）。

**验收**
- [ ] 双源配置（一允许封一不允许可拉）拉取后规则数与源策略精确一致。
- [ ] 冲突 value 按优先级保留；旧单源配置启动报明确错误（无静默兼容）。

### F720 CrowdSec 社区名单接入 — 规模 M

**范围（In）**
- CrowdSec CTI 社区 blocklist 下载器（JSONL：value/scope/labels/expiration/confidence）；API key 走环境变量 `AISAFEGUARD_CROWDSEC_KEY`（最高优先）/凭据管理器——config 无秘密原则。
- 单 IP 条目入库（source=crowdsec，kind 取首个行为标签如 ssh-bf）；**网段条目一期丢弃 + 计数**（meta 落账，GUI 可见丢弃比例——F770 是否做的决策依据）；TTL = min(expiration, 7d)。
- 许可条款核对写进 FEDERATION.md（CTI 数据许可与免费档限流是数据许可，非软件开源许可）。

**红线 / 负路径**
- API key 缺失 = 该源跳过 + 明确告警（不做静默降级，对齐 webhook 签名先例）。
- 名单爆炸防护：单轮入库上限 + 限流（对齐现有 500 条/轮治理）。

**验收**
- [ ] 真实 key 拉一轮：入库条数 / 网段丢弃数可见；auto_block 开启时规则数与单 IP 条目数一致（内网除外）。
- [ ] 无 key 启动 = 明确告警不拉取；断源重试不产生空情报覆盖（现状保持）。

## 第二批：舰队实战实验（0.7.1，含 2-3 周日历等待）

### F740 实验设计与采集脚手架 — 规模 S

**范围（In）**
- `docs/EXPERIMENT.md`：**口径先于跑动钉死**——①噪声基线：日均事件量/独立攻击者数/Top 源；②**印证命中率 = 被 ≥2 节点独立观测的攻击者键数 / 攻击者键总数**（0.6 核心假设的主指标）；③误报候选 = mark_fp 次数 / 千事件；④AI 建议抽样 20 条人工评级。判据预注册：印证命中率 ≥20% = 0.6 假设成立；<5% = 假设重估；中间 = 延长观察。
- `scripts/experiment-report.py`：从 export-events/audit/sqlite 抽上述口径出报告（attach 模式复用，纯 stdlib）。

### F745 舰队部署与运行 — 规模 S（工程）+ 2-3 周日历

- 3×廉价 overseas VPS（1 台兼任协调者）；部署手册复用 FEDERATION.md（init-ca/issue-cert/expect/配置）；安全组只放行蜜罐诱饵端口，API 走 SSH 隧道。
- 配置纪律：intel=CrowdSec 单源（F720）、1 台开 AI 慢路径（成本受控）、auto_block 开、蜜罐全开。

### F748 实战报告 — 规模 S

- `docs/REAL-WORLD-REPORT.md`：四个数字 + 意外发现 + 结论回填本路线图；失败结论照写（印证命中率≈0 也是有效产出——那是 0.6 假设重估的依据，不是实验失败）。

## 第三批：规则弹药（数据驱动，0.7.1）

### F750 ET Open 精选子集 — 规模 M

**范围（In）**
- 从 ET Open 只取**引擎 IR 已支持子集**的 HTTP 类规则（content/nocase/offset/depth/distance/within/pcre 白名单/threshold/classtype），初筛 ≤200 条；
- 与批次二并行开发：选包/接管道/基准不需要实验数据；**终选 ≤50 条**用舰队回放数据校准误报后定版，进**默认关闭**的可选规则包（demo.rules 同款治理：整包加载/SHA-256 留痕）；
- 匹配性能基准：规则包在载入规模下的单事件匹配延迟（现无基准，补一个简单基准测试钉住）。

**红线（选包标准三条，预注册防跑完找补）**
- **误报是唯一硬淘汰项**：真实流量上对良性请求频繁告警的规则，扔或 threshold 限流；
- **零命中不是淘汰项**：签名库是保险单不是拟合模型——不响的规则保留，防「拿这两周的攻击拟合库、未来失明」；规则包的生命力靠 ET 上游每日更新 + 本管线脚本化周期重跑刷新；
- **协议不可达才是淘汰项**：我们输入面永远看不到的协议（如 DNS）规则是死重，清理只为卫生。

**红线（通用）**：规则包默认关；误报治理走既有 fp 抑制管道，不为「命中率」放松 classtype 白名单。签名抓已知手法，0day 由蜜罐（摸到即留痕）与频次/行为引擎兜底——分工明确，规则库陈旧的最坏后果是安静不是危险。

**验收**
- [ ] 精选包在舰队回放数据上误报率有数；默认关基线不变。

## 第四批：AI 调参者（0.7.2）

### F760 AI 策略调参建议管道 — 规模 L

**范围（In）**
- proposal schema 扩展三类 action（与 block/credential_spray 同一严格校验管道）：`promote_rule{rule_id}` / `retire_rule{rule_id}` / `tune_detection{param,value}`——param 白名单枚举（扫描端口数/窗口/频次阈值/TTL 等），枚举外整条作废。
- 周报分析任务：7d metrics + detections + fp_feedback + 规则现状进 prompt（`<metrics>` 段，同 org 段注入先例）；产出调参建议进慢路径，**人工确认才应用**（apply 映射到 promote/移除/改配置）。管道与护栏**与批次二并行开发**（本机 7d metrics 够开发用）；建议质量的最终判定引用 F748 真实数据。
- GUI 审批入口复用 proposals 管道；全部落审计。

**红线 / 自反馈护栏（三层，缺一不做）**
- 调度限频：每 7 天一轮；单轮建议 ≤5 条；
- 参数冷却：同一参数被调后 30 天内不再入建议；
- 人工确认：无任何自动应用路径；AI 永不直接写 config。

**验收**
- [ ] 合法 tune 建议走完全管道（提议→确认→生效→审计）；非法 param/超频/冷却期内建议被拒并有留痕。

## 挂起：数据驱动（F720 一期统计出来再拍板）

### F770 防火墙网段支持 — 规模 M-L

- 背景：CrowdSec 名单大量条目是 CIDR 网段；当前三层后端只吃单 IP。
- 一期（F720）只收单 IP 并统计网段丢弃比例；**若丢弃比例高**（初步判断会高）→ 二期：nftables interval 集合 + Windows COM 子网掩码写法 + XDP 明确降级（LPM trie 或「网段不进快速层」文档化）。
- 红线不变：细粒度规则不镜像进 XDP 的既有原则（防语义放大）照抄。

## 跨任务红线汇总（0.7 全批次适用）

1. 0.6 全部红线不变：内网/回环永不自动封；跨节点建议而非命令；AI 不自动处置；凭证材料不出节点；`forbid(unsafe_code)`。
2. **源分级后全局保险仍在前**：任何源的条目都过内网保护/TTL/审计，源策略只能收紧不能放宽全局保险。
3. AI 调参者自反馈护栏三层是验收项，不是建议。
4. 实验判据预注册，跑完不许改口径。

| 风险 | 预案 |
