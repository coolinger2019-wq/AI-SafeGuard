# 实战实验设计（0.7 F740，口径预注册）

> **本文件在实验开始前写定，实验期间不得修改口径**——跑完往回找补等于没有实验。
> 所有数字由 `scripts/experiment-report.py` 从产品数据库确定性生成，人工只做判读。

## 一、目的与两段式设计

产品定位是**内网优先组合防御**。两段实验各答各的问题：

| 段 | 场景 | 回答的问题 | 需要的机器 |
|---|---|---|---|
| 第一段 | 公网单点实战（1 台 overseas VPS，2-3 周） | 真实互联网的**噪声基线**：事件量、攻击者构成、误报率、蜜罐抓到什么 TTP——喂 ET 规则筛选（F750）与检测调优方向 | 1 台（不需要联邦） |
| 第二段 | 内网联邦红队演练（1-2 天） | **设计场景**下印证全链路是否成立：内网横向源被多机独立观测 → 协调者印证 → 成员复验命中 → 建议闭环——喂 0.6 假设检验 | 全部现有（Windows 主机 + WSL + 局域网另一台设备） |

（可选扩展：第一段数据有意思时扩公网多节点，验证联邦层机制在真实持续负载下的正确性——
不冒充内网场景检验。）

## 二、口径（四组，预注册）

### ① 噪声基线（第一段）
- 日均事件量（events 按日计数，分 kind）
- 独立攻击者数：`COUNT(DISTINCT remote_ip)`，kind ∈ {honeypot_hit, detection}
- Top 20 源及占比
- 在库情报条数按源分布（intel 表）

### ② 印证命中（第二段，设计场景口径）
- **触发**：演练源（A 机内网 IP）在 B/C 的观测均到达协调者，且协调者事件流产出「组织印证」
- **复验**：≥1 个成员端 org_events 账本出现该印证且 detail = hit
- **闭环**：印证驱动的组织建议（block:内网源）被成员**四关复验拒绝**（内网保护）——这是预期行为，
  记录为「保护生效」而非失败；如需观察建议采纳路径，另用公网测试源单独演练

### ③ 误报候选（两段通用）
- `fp_feedback` 行数 / 千事件（用户主动标记口径）
- proposals 按 status（applied/dismissed/pending）× 来源（本地 AI / fed:*)分布
- dismiss 率 = dismissed / (applied + dismissed)

### ④ AI 建议质量抽样（第一段，开 AI 的节点）
- 实验期随机抽 20 条建议，逐条对证据链打分：
  - **正确**：多信号印证（蜜罐命中 + 快路径独立命中，或情报对上）
  - **存疑**：单信号、证据单薄
  - **错误**：证据显示良性（监控服务/搜索引擎爬虫/云厂商 NAT 出口）
- 产出「正确:存疑:错误」比例——直接决定 F760（AI 调参者）的建设方向

### 口径修正表（已知统计坑，读数前先过）
| 坑 | 修正 |
|---|---|
| scan 判定结构性无载荷（0.3.4） | 扫描类只看数量与源，不看载荷内容 |
| WSL AF_PACKET 环回双投递 | 第二段若用 WSL 节点，计数除 2 或改用实机 |
| 跨机时钟 | 演练机器全部 NTP 对时；印证窗口按节点本地时间戳 ±容差 |
| **运营者自封**（2026-10-01 首日实测） | 对蜜罐多端口探针会触发 scan 判定 → nftables 封运营者源 IP（TTL 30min，SSH 一并被丢）——预期行为，是数据不是事故；管理员操作避开探针时段或用厂商控制台；探针产生的检测事件本身就是「外部视角」的真数据，照常入分析 |
| rule_id 仅 0.7 起落库 | 实验起跑后产生的 detection 才有按规则统计 |

## 三、数据采集 SOP

1. **完整性先行**：任何取数先 `aisafeguard verify-log`（哈希链校验），失败的数据不进分析。
2. **事件流**：`aisafeguard export-events <out.jsonl>`（JSONL 含 rule_id/http_hint/tls 指纹）。
3. **富数据**：直接拷 SQLite **三件套**（.db/.db-wal/.db-shm，运行中拷贝也合法）或停机后拷单文件；
   凭证库（credentials.db）单独拷——分析只统计数量，字段含掩码与哈希，无明文。
4. **协同面**：协调者 `fed audit <out.json>` 导成员/吊销/原始信封尾部。
5. **取回通道**：SSH 隧道 + `--print-token` + 本地 API，或直接 scp 文件（attach 模式已被 e2e 验证）。

## 三点五、远程查看节点界面（F740 配套，`--remote`）

节点的 GUI 是桌面程序，VPS 上跑的是 headless（无界面）。**远程看节点的正路 = SSH 端口
转发 + GUI 远程控制台模式**（`aisafeguard --remote`，F740 配套能力）：

```bash
# ① 本机起 SSH 隧道（保持开着）——把节点回环 API 映射到本机
ssh -N -L 17420:127.0.0.1:7420 root@<节点IP>
# ② 取节点 token（节点上执行；或 scp 回 /var/lib/aisafeguard/api-token）
cat /var/lib/aisafeguard/api-token
# ③ 本机用 GUI 远程模式连本机转发端口
aisafeguard --remote http://127.0.0.1:17420 --token <节点token>
```

GUI 打开即该节点的完整界面（仪表盘/事件/防火墙/组织面板），数据实时来自节点 API。
安全边界：API 永远只听节点本机回环（公网不可达），跨机访问只能经 SSH 隧道 + token；
`--token` 值会进本机进程列表，介意可用 `--token-file <路径>`（scp 回来的 token 文件）。
多节点 = 开多个隧道端口（17420/17431/...）+ 多个 GUI 实例，或轮流连。

## 五、预注册判据

**第一段（数据质量判据——本段是采集，不是达标考试）：**
- 连续运行 ≥14 天，非正常退出 ≤2 次且有日志
- ≥50 个独立外部攻击者（公网蜜罐 14 天的常识下限；低于此说明部署面有问题，先修部署）
- 误报候选率与 Top 源构成成为 F750 规则筛选与检测调优的输入

**第二段（机制判据——三档）：**
- **通过**：演练源在 B/C 均产生观测 + 协调者产出印证 + ≥1 成员复验命中
- **部分通过**：印证产出但复验未命中（复验逻辑或时间窗问题——修）
- **不通过**：无印证产出（0.6 核心假设在设计场景不成立——重估，联邦降级为告警聚合层）
- 演练不触发**不是失败**，是 0.6 假设重估的依据

## 六、成本与风险

| 项 | 估算 |
|---|---|
| 第一段 | 1×最低配 VPS（月付可停），带宽与磁盘余量 5GB 级即可 |
| 第二段 | 零采购（现有机器）；演练流量仅限自有内网 |
| 人工 | 部署半天 + 每日取数 5 分钟 + 报告判读半天 |

风险：VPS 供应商安全组/滥用条款（蜜罐端口放行需自查）；AI Key 成本（只开 1 台、分析间隔放宽）；
公网暴露的只有蜜罐端口与（可选）fed 面，API 永远只听 127.0.0.1。
