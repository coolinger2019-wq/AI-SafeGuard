# ROADMAP-0.5.9:蜜罐深化专项(Honeypot Deepening)

> 定位:0.5.4-0.5.6「单机地基收口」之后的蜜罐增强批次。仍属单机能力,**不触碰 0.6 多机协同**。
> 动机:蜜罐是系统的事件入口,当前 4 种低交互协议 + 无假 Shell + 无 canary,是整个传感层最短的一块板;入口浅 → 检测与 AI 慢路径收到的证据质量低。
> 总目标:**抓得深(中交互仿真)、抓得广(协议扩充)、抓得值钱(凭证情报)、藏得住(反识别)**,同时守住本仓库一贯红线:新能力默认关、内网永不自动封、误报一键闭环、负路径可复现实测。
> 参考对象:HFish 学产品化(模板/蜜饵),Cowrie 学假 Shell 仿真设计(BSD 协议,借鉴设计不抄代码),OpenCanary 学协议扩展思路。
> 编号约定:本文件任务号 `Hxxx`。若 0.5.7/0.5.8 已有占位批次,本文档可整体顺延为对应版本号,任务编号不变。
>
> **切分决议(2026-09-29 可行性评估后)**:本文档拆为三个发布批次——**0.5.9 = 第一批(仿真深度:H101-H105 + H110 + H120)**、**0.5.10 = 第二批(情报价值:H200 + H210)**、**0.5.11 = 第三批(产品化与反识别:H300/H310/H320/H400)**。文件名保留 0.5.9(首个发布批次)。评估结论:九个任务中八个是现有架构的顺势扩展;唯一架构级新增是 H100 引入 russh(当前 "ssh" 蜜罐只发 banner 不说 SSH 协议)。三处范围修正已直接写进对应任务节,动工前不再另行讨论。

## 第一批:仿真深度

### H100 SSH 假 Shell(中交互)— 规模 L

**背景**:README 已知限制「非中交互蜜罐(无假 Shell/命令执行)」。低交互只能采集认证尝试,中交互才能拿到攻击者的完整操作序列(TTP 证据),这是 AI 慢路径最需要的输入。

**范围(In)**
- 认证通过后进入假 Shell 会话:假 prompt(`user@host:~$`,主机名/用户名可配)。
- 命令仿真白名单制(**白名单而非黑名单**):首版支持 `whoami / uname -a / id / pwd / ls / cat / ps / ifconfig|ip addr / netstat / wget / curl / chmod / history / exit`。
- 假文件系统视图:静态目录树(`/etc/passwd`、`/home`、`/var/www` 等),`cat` 返回内置诱饵内容(与 H210 的 canary 内容呼应)。
- `wget/curl <url>`:记录 URL 与参数,**默认不真正发起下载**,事件含完整命令行。(切分修正:sinkhole 模式——DNS 假应答——从 0.5.9 切出,全仓无 DNS 能力,执行面归 0.6 情报通道;H310 的 `sinkhole_domain` 建议类型一并移除。)
- 会话限制:最大命令数(默认 50)、会话空闲超时(默认 120s)、总会话时长上限——防自动化脚本无限挂着刷事件。
- 每条命令产生结构化事件进事件总线(复用现有 `honeypot` 事件族,新增 `interaction` 字段:逐命令数组,载荷按现有截断策略留存)。

**范围(Out)**
- 不做可执行后端(假 Shell 永远不 fork 真实进程)。
- 不做交互式全终端仿真(如 vi/top 的伪终端),首版保持「行模式」。
- 不实现 Cowrie 式假文件系统可写层。
- sinkhole / DNS 假应答(0.5.9 不做,归 0.6)。

**红线 / 负路径**
- 假 Shell 收到的任何输入都按「数据」处理,永不拼接进任何系统调用。
- 命令解析失败/未知命令 → 返回通用 `command not found` 并记录,**不泄漏「我是蜜罐」的特征**(错误文案对齐真实 bash)。
- 防逃逸注入:`;` `|` `&&` 等组合只解析首个命令,其余原样记录。
- 下载诱导不落地真实文件,防止蜜罐反被用作跳板存储。
- 会话限制触发时优雅断开(banner 风格对齐 OpenSSH 正常断连),不返回错误码细节。
- **全局交互会话并发上限(评估新增)**:假 Shell 会话长挂会占满现有全局 64 并发信号量,饿死全部监听器;交互会话独立设小上限(默认 8),触发即优雅拒绝并留事件,列入 THREAT_MODEL「蜜罐被打」攻击面。

**验收**
- [x] paramiko 回放脚本:登录 → 执行 5 条内置命令 + 1 条未知命令 → 事件含逐命令序列与假文件系统响应。
- [x] `scripts/demo-honeypot-deep.sh` 独立演示(假 Shell+MySQL+Redis),一键演示可见事件。
- [x] 负路径实测记录进 `docs/NEGATIVE-PATH-TESTING.md`:组合命令注入、超长输入(≥4KB)、二进制乱码、会话超时。
- [x] 蜜罐本身被打(假 Shell 逃逸尝试)列入 `docs/THREAT_MODEL.md` 新增攻击面条目。

**切分:0.5.9 内细分五个子任务(序贯推进)**

- **H101 russh 集成 spike(S,前置)**:workspace 引入 russh,显式选 `ring` 后端特性(仓库 rustls/rcgen 刻意锁 ring——Windows 构建无 CMake/NASM,警惕 feature 合并悄悄引入 aws-lc-rs,做法对齐 0.3.6 rustls 的先例);过 cargo audit / cargo deny / clippy 三道门;最小服务端:握手完成 → 任意凭证放行 → 打开 shell channel 回显假 prompt。**退出标准**:paramiko 实连登录成功 + 三道门全绿;失败则带证据停下重估方案,不硬闯。
- **H102 蜜罐 crate 模块化 + 会话模型重构**:761 行单文件拆模块(监听/会话/协议/事件);`HoneypotHit` 增 `interaction` 逐命令数组(serde 可选字段,存量事件与哈希链兼容);交互会话独立并发上限;现有 4 协议行为回归(现有测试不动全过)。
- **H103 命令仿真层**:白名单命令解析 + 假文件系统静态树;`cat` 返回内置诱饵内容(为 0.5.10 H210 canary 预留接点);组合命令(`;` `|` `&&`)只解析首个;未知命令文案对齐真实 bash。
- **H104 SSH 端到端接线**:russh handler 接仿真层;prompt/主机名/用户名可配(内置默认值,模板参数化留给 0.5.11 H300/H320);host key 启动生成并持久化到 `<data_dir>/honeypot/`(fed 证书路径模式);认证失败固定延迟;`[honeypot.shell]` 默认关 + `default_config_security_baseline` 断言 + `restart_required` 契约三处同步。
- **H105 验收与负路径**:paramiko 回放脚本(`scripts/replay-ssh-shell.py`);`demo-attack.sh` 假 Shell 段;NEGATIVE-PATH-TESTING 四项实测(组合注入/≥4KB/二进制乱码/会话超时);THREAT_MODEL 两条攻击面(逃逸尝试/并发饿死)。

### H110 MySQL / Redis 蜜罐 — 规模 M

**背景**:数据库蜜罐是抓僵尸网络(Mirai/Gafgyt 类)与口令爆破证据价值最高的协议族,僵尸网络 payload 常直连 3306/6379。

**范围(In)**
- **MySQL**:实现握手协议(服务端 greeting 版本号可配,默认贴近真实版本)、认证失败凭证采集、登录失败文案对齐真实 mysqld;认证后也支持简单语句假响应(`SELECT` 返回空结果集 / `SHOW` 返回内置假数据),语句全部记录。
- **Redis**:RESP 协议解析;`AUTH` 采集口令;`INFO/CONFIG GET/SLAVEOF/GET/SET` 等返回假响应(让攻击脚本继续运行以采集更多行为);写命令与来源 IP 记录。
- 两者事件沿用现有蜜罐事件结构,凭证统一进 H200 凭证库。
- 复用 H320 的 banner 可配机制(本任务先内置默认值)。
- **默认监听表不新增 mysql/redis 条目**(切分修正):新协议以「用户显式配置监听」为开启方式,天然满足「新能力默认关」;`default_config_security_baseline` 补「默认监听列表不变」断言。

**范围(Out)**:不做真实查询执行;不支持 MySQL  prepared statement 全协议。

**红线 / 负路径**
- 协议解析器只读不解码执行,畸形包 → 断连并记录,不 panic(对齐现有蜜罐的模糊测试护栏)。
- 假响应数据用内置常量,**不得包含任何真实业务数据**。

**验收**
- [x] `mysql -h127.0.0.1 -P3307 -u<user> -p` 实连:错误凭证 → 事件;正确格式交互 → 假结果集。
- [x] `redis-cli` 实连:`AUTH`/`SET`/`INFO` 假响应回放,事件完整。
- [x] fuzz:随机字节流打两个端口,服务不崩、事件有记录(复用现有结构化模糊测试)。

## 第二批:情报价值

### H200 蜜罐凭证采集与本地喷洒检测 — 规模 M

**背景**:蜜罐收集的 用户名/口令 对,与本地真实账号做交集,是「凭证喷洒 / 内部口令泄露」最高信度的信号——HFish 只采集不分析,这是本项目的差异化能力,也是 AI 慢路径的最佳落点。

**切分修正(0.5.10,选型评估期已定)**:口令加盐哈希用 **argon2**(RustCrypto 成熟库,净新增依赖,过供应链门禁即可);Windows 本地账号枚举用 **NetUserEnum**(windows 系 crate,与现有 windows-firewall/windows-service 依赖风格一致),不走外部命令解析输出。

**范围(In)**
- 凭证库:所有蜜罐协议(SSH/Telnet/MySQL/Redis/HTTP 表单)的 用户名/口令 对统一入库。
  - **口令以加盐哈希存储**(用于比对与频次统计,不还原、不展示);用户名明文(用于喷洒比对)。
  - 沿用现有「HTTP 密码字段脱敏不落库」约束——展示层一律掩码。
- 本地账号快照:启动时 + 可配周期,枚举本机账号名(Linux `/etc/passwd` 人类用户;Windows 本地用户枚举),**只取用户名集合,不取哈希**(避免触碰真实口令数据)。
- 喷洒检测:蜜罐凭证用户名 ∩ 本地账号集合 ≠ ∅ → 高严重度事件 `credential_spray`,直推快路径(自动封禁仍受内网保护约束)并标记 AI 慢路径优先分析。
- 频率维度:同一来源 IP 跨协议撞库(如 SSH + MySQL 同口令)聚合为单事件。

**范围(Out)**:不做与外部泄露库(HIBP)的联网比对(离线工具属性,留 0.6 情报通道);不做真实口令强度评估。

**红线 / 负路径**
- 口令哈希库文件权限 0600,事件与 API 输出永不包含口令明文与可逆信息。
- 本地账号快照只存用户名,文档中明示该设计决定(THREAT_MODEL 补充)。
- 比对逻辑在独立模块 + 单测:绝不能让蜜罐事件携带真实本地账号哈希。

**验收**
- [ ] 用与本地用户名同名的账号访问蜜罐 → `credential_spray` 高严重事件,GUI 可见来源与证据链。
- [ ] API 全字段扫描测试:任何接口不返回口令明文(自动化断言进测试套件)。
- [ ] 凭证库落盘文件权限与掩码展示,实测记录进 NEGATIVE-PATH-TESTING.md。

### H210 Canary 文件(蜜饵)— 规模 M

**背景**:README 已知限制「canary 文件未实现」。蜜饵把诱捕从「端口等人来」扩展到「主动埋雷」。

**范围(In)**
- 蜜罐内 canary 资源(第一期,纯蜜罐侧,无系统侵入):
  - HTTP 蜜罐内置可下载诱饵:`/backup.zip`、`/.git/config`、`/id_rsa`、`/db.sql`——文件内容带**水印 token**(节点标识 + 时间戳,可配置密钥)。
  - 下载行为本身即事件(比「端口被碰」强得多的信号:攻击者在主动翻东西)。
- 文件系统 canary(第二期,**切分修正:v1 仅 Linux**):
  - Linux:配置目录下放置诱饵文件(假 `.env`、假 `config.yml`),inotify 监控读取(notify/inotify crate 为净新增依赖)。
  - Windows:**v1 不做**。用户态没有「文件被读取」的对等通知 API(ReadDirectoryChangesW 只报属性/名称变更,不报读),ACL 拒绝方案信号语义不同且复杂度高——不做打折的伪对等,README 明示差异(与 eBPF 仅 Linux 的降级口径完全一致)。
- 水印解析工具:`aisafeguard canary-decode <token>` → 来源节点/投放时间,支撑外传溯源。

**范围(Out)**:不做邮件蜜饵(钓鱼);不做诱饵文档的宏/web bug。

**红线 / 负路径**
- 诱饵内容全部是合成的,结构与真实文件一致但数据为零值/明显假数据,防止被当真实数据引用。
- 文件系统 canary 的监控必须只读监听,自身不产生可被利用的提权面。
- 诱饵文件路径与文件名可配,避免与用户真实路径冲突(配置冲突时启动拒绝并提示)。

**验收**
- [ ] `curl http://127.0.0.1:8081/backup.zip` → 下载成功且事件含水印;`canary-decode` 还原投放信息。
- [ ] Linux 上读取诱饵文件 → 告警事件;Windows 降级行为文档化实测。
- [ ] 负路径:诱饵被正常业务进程误读(可配抑制)不误报高频刷屏——沿用现有抑制机制。

## 第三批:产品化与反识别

### H300 蜜罐页面/协议模板机制 — 规模 M

**背景**:学 HFish 的模板化产品形态——把「造假业务系统」做成可配置资产而非硬编码。现有 HTTP 假登录页与敏感路径诱饵内置在代码里,新增一个假 OA 页面需要改代码。

**范围(In)**
- `templates/` 目录约定:每个模板一个目录,`template.toml`(协议、端口、banner、匹配路径、事件标签)+ 资源文件(html/静态文件)。
- HTTP 模板:页面 HTML、表单字段名、POST 提交行为、敏感路径列表全部模板可配;内置现有假登录页为默认模板(行为与上一发布版 0.5.8 完全兼容)。
- 协议模板注册表:SSH/Telnet 的 banner、假 Shell 的 prompt 与假文件系统视图也纳入模板参数。
- 模板加载治理对齐规则引擎的「整包加载」哲学:**单模板解析失败 → 该模板拒绝加载并告警,不影响其他模板与内置默认**。
- 热更:模板目录变更可检测重载(需重启项与热更项分界写入 `AppConfig::restart_required` 契约)。

**红线 / 负路径**
- 模板里的 HTML 按「数据」渲染,渲染上下文不接触 GUI/webview 的可执行面(egui 仅文本展示,已天然隔离,写进 THREAT_MODEL 即可)。
- 模板不得覆盖真实监听端口——与已有真实服务端口冲突时启动拒绝(沿用现有占用检查)。

**验收**
- [ ] 不改一行代码,新增一个「假 Grafana 登录页」模板(放 html + toml)即生效。
- [ ] 损坏模板 → 仅该模板告警拒绝,其余与默认页面正常。
- [ ] 升级用户无模板目录 → 行为与上一发布版(0.5.8)逐字节一致(回归断言)。

## 跨任务红线汇总(全批次适用)

1. **新能力默认关**:H100 假 Shell、H110 新协议、H210 文件系统 canary、H300 自定义模板,全部 `enabled = false` 起步,显式开启。
2. **内网/回环永不自动封**硬约束不变;H200 高严重事件同样受误报抑制与内网保护约束。
3. **传感器/执行器分离不变**:所有新蜜罐能力落蜜罐 crate,经事件总线接入,`Firewall` trait 窄口不扩。
4. **双平台对等或显式降级**:Linux-only 能力(eBPF、inotify)按现有口径降级,README 明示。
5. **AI 不自动处置**红线不变:H310 扩展的建议类型全部走默认人工 + 灰度 TTL 现有闭环。
6. 全仓库 `forbid(unsafe_code)` 不变;新协议解析器必须过模糊测试护栏。
