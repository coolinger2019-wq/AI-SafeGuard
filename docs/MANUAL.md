# AI-SafeGuard 安全中心 · 集成操作手册

本手册随程序内置（离线可看），讲「怎么用」不讲「怎么实现」；实现细节见仓库 docs/ 目录的架构与威胁模型文档。

---

## 这是什么

AI-SafeGuard 是一台装在你自己电脑上的**终端入侵诱捕与自动封禁盒子**：

- **蜜罐**：在可疑端口伪装成 SSH、Web、Telnet、MySQL、Redis 服务，等攻击者上门，记录对方的一切动作；开假 Shell 后连输的每条命令都留痕。
- **快路径检测**：蜜罐被高频触碰、规则包命中时，自动把来源 IP 封禁一段 TTL（内网/回环地址永不自动封禁）。
- **AI 慢路径（可选）**：把证据交给大模型分析，产出带理由的封禁建议，默认等你人工确认，且都是短 TTL 灰度执行。
- **误报一键闭环**：任何判定你不认可，点一个按钮，同类处置立即停止并被抑制一段时间。

所有能力默认克制：深检、假 Shell、蜜饵、规则包、AI 等默认关闭，要用哪个开哪个。

## 快速上手

1. 启动程序（Windows 直接运行；Linux 可 `--headless` 或装 systemd 服务）。首次启动会生成带注释的 `config.toml` 和数据目录。Windows 下若未提权且没装服务，会自动弹出管理员授权提示（UAC）——同意后自动重启进入完整功能；拒绝也能运行，只是防火墙相关功能受限；安装服务后 GUI 以普通权限连接服务，不再弹提权。
2. 什么都不用配：默认四个蜜罐监听（2222/8081/2323/1337）已经在等人来。「仪表盘」和「事件」页很快会出现探测记录。
3. 想要更多能力，进「设置」逐项开启；每项都标注了默认状态和是否需要重启。
4. 本机访问 REST API 时，token 用 `aisafeguard --print-token` 查看。

## 界面导览

### 仪表盘

打开后的第一眼：过去 24 小时蜜罐被碰了多少次、有多少个不同来源、自动封禁了多少、AI 建议了多少。底部是价值指标（封禁是否被误报纠正等），用于自查产品有没有在帮倒忙。

### 事件

全部安全事件的流水，按时间倒序。点任意一条看证据明细（HTTP 提示、逐命令记录、指纹等）。检测类事件右侧有「误报」按钮——点了就进入抑制期，自动封禁跳过该来源。

### 防火墙

当前生效的封禁规则列表（含 AI 建议应用产生的灰度规则和转正规则）。可手动添加/删除规则；到期时间到了自动解封，不需要手动清理。

### 蜜罐

蜜罐的所有事情都在这一页完成：

- **状态列表**：六种协议（SSH/HTTP/Telnet/Generic/MySQL/Redis）全部列出，每行一条。●「运行中」表示端口已绑定对外服务；「已停止」通常是端口被占用或手动停了；没配置的协议显示「未配置」和一句能力介绍，点「+ 添加」即建一行并立即启动。
- **热切换开关（0.5.12）**：每行的「启动 / 停止」按钮**即时生效**，不用重启程序——停了就是真的不监听了，启动失败（如端口被占用）会在事件页留痕。切换结果同时写入 config.toml，重启后保持一致。
- **就地配置**：行内「配置」展开编辑名称/协议/端口（这类结构改动需重启生效）；假 Shell、凭证采集、蜜饵开关在下方分区直接改。这里与「设置 → 蜜罐」是同一份草稿，在哪边改都行。

### AI 助手

展示每次 AI 分析的结论、逐条建议（来源 IP / 理由 / 严重度 / 灰度时长），并可逐条「应用」「收弃」。AI 不自动处置任何东西——除了你开了自动应用的场景，而且也只做短 TTL 灰度。

### 设置

按功能域分页：外观、AI 分析、检测与感知、蜜罐、通道与告警、关于。改动先存草稿，点「保存设置」才落盘；需要重启的项保存后会明确列出。

### 帮助

就是本手册。

## 常见任务

### 开启假 Shell（SSH 中交互）

「设置 → 蜜罐 → 假 Shell」勾选 SSH（或 Telnet），可顺手改假 Shell 的用户名/主机名（让伪装更像你的环境），保存后按提示重启。之后用任意口令连接蜜罐 SSH 端口即可进入命令仿真会话，「事件」页能看到逐命令记录。假 Shell 永远不会执行真实命令。

### 增加一个监听器（例如 Redis）

「设置 → 蜜罐 → 监听表」点「+ 添加监听器」，默认就是一行 MySQL（3307）；把协议换成 Redis、改个不冲突的端口，保存重启。「蜜罐」页会出现新卡片。mysql/redis 不在默认监听表里，属于显式开启。

### 放置蜜饵（canary）

「设置 → 蜜罐 → 蜜饵 canary」勾选启用：HTTP 蜜罐会开始内置 `/backup.zip`、`/id_rsa` 等诱饵资源，谁下载谁就会留下带水印的事件。想埋文件系统蜜饵（谁读文件谁告警），在 `config.toml` 的 `[honeypot.canary].fs_paths` 里写绝对路径（仅 Linux）。诱饵内容里的水印 token，外传后用 `aisafeguard canary-decode <token>` 可还原来源节点与投放时间。

### 做一个假业务系统（模板）

想伪装成 Grafana、公司 OA 或任何登录页？在模板目录里放一个文件夹：
一个 `template.toml`（协议、端口、表单字段名、敏感路径）加一个 `page.html`，
重启后就多了一个对应的蜜罐监听器。单模板写坏了只会拒绝那一个并告警；
改了页面内容约 5 秒自动热重载。目录约定与完整字段见 `docs/deployment.md`。

### 改对外标识（banner）

`config.toml` 的 `[honeypot.fingerprint]` 里可以改 SSH 版本串、Telnet 问候语、
MySQL 版本、HTTP Server 头——建议抄你环境里真实服务的版本。改得好能降低被
指纹库认出的概率，但不承诺对抗主动探测（详见 `docs/deployment.md`）。

### 开启 AI 分析

「设置 → AI 分析」勾选启用，填 OpenAI 兼容地址与模型名，Key 存到系统凭据管理器（不写进配置文件）。分析默认按间隔轮询；建议默认人工确认。内网无外联也可用：把地址指向本地推理服务即可。

### 开启规则包

准备本地规则文件（Suricata 子集语法，示范见仓库 `crates/aisafeguard-rules/demo.rules`），「设置 → 检测与感知 → 规则子集引擎」里填路径并启用。文件变化自动整包热重载；一条不合法就整包拒绝——不会加载半套规则。

### 改了设置为什么不生效

设置页标注「需重启」的项（蜜罐监听、假 Shell、API 端口、采样模式、XDP 等）保存后要重启程序；其余（检测阈值、AI 参数、转发通道等）保存即热更生效。

## 出了事看哪里

### 怀疑被入侵

「事件」页按时间线看：蜜罐命中 → 检测判定 → 封禁执行，一条链都在。中交互会话能看到攻击者敲的每条命令。AI 建议的「证据链」展开后可以看到它依据了哪些事件。

### 封错了 / 太吵

事件右侧「误报」按钮：标记后解除该来源的全部自动封禁、收弃其待处理建议，并在抑制期内不再自动处置它（人工手动封禁不受影响）。抑制时长在设置里可调（默认 14 天）。

### 想核实记录没被篡改

事件是哈希链存储。`aisafeguard verify-log` 离线校验整条链是否完整；`aisafeguard export-events <文件>` 导出留档。

## 配置文件

全部配置项见仓库 `docs/config.example.toml`：每一项都有一句人话说明 + 默认值 + 改了会怎样。把想要的部分抄进你自己的 `config.toml` 即可。默认安全基线有自动化测试守护——深检/规则/XDP/蜜饵等默认永远关闭，升级不会悄悄打开它们。

## 能力边界（先说清楚）

- 蜜罐是仿真不是真机：假 Shell 有命令白名单，超出范围的都按「command not found」处理。
- 自动封禁只对公网来源；内网/回环地址永远不自动封。
- AI 是分析员不是决策者：一切处置默认人工确认，灰度 TTL 到期自动解封。
- 本机离线可用；AI、情报订阅等联网功能全部可选，不联网只影响对应功能。
- 详细的非目标与残余风险见仓库 README「已知限制」与 THREAT_MODEL。
