# 部署与反识别指南（0.5.11 H320 / H300）

> 本文档讲「怎么把蜜罐部署得更像真实业务、更不容易被一眼看穿」。
> 立场先说清楚：这是**成本可接受的混淆**，不是对抗性隐身——协议行为层面的
> 差异不可能归零（见文末残余风险）。

---

## 一、Banner / 指纹参数（[honeypot.fingerprint]）

蜜罐对外的第一眼由四个参数决定，默认值与内置值逐字节一致：

| 参数 | 默认值 | 说明 |
|---|---|---|
| `ssh_banner` | `SSH-2.0-OpenSSH_9.6` | SSH 协议版本串（发送时自动补 CRLF） |
| `telnet_greeting` | `Welcome to Ubuntu 22.04 LTS\r\nlogin: ` | Telnet 问候语（按字面原样发送） |
| `mysql_version` | `8.0.36` | MySQL greeting 版本号 |
| `http_server` | `nginx` | HTTP `Server` 响应头 |

**选择建议**：

1. 对齐你环境里真实服务的版本——同一内网里跑着 `OpenSSH_9.2` 的机器旁边
   出现一台 `9.6` 的 SSH，比版本旧不旧更扎眼。先在真实服务器上
   `ssh -V` / `mysql --version` 再抄过来。
2. 不要追新到尚不存在的版本号——nmap 与指纹库的版本签名是按真实发行动态
   建的，"未来版本"反而是特征。
3. HTTP `Server` 头与真实站点保持一致（全是 nginx 就写 nginx）。
4. 验收方式：`nmap -sV --script=banner,ssh-hostkey <host> -p 2222` 应识别为
   所配置的服务与版本；常见蜜罐识别脚本（如那些查找 Cowrie/HFish 特征的）
   跑一遍对比加固前后——允许残余差异，不允许命中已知蜜罐指纹条目。

## 二、模板（[honeypot.templates]）——把假业务做成资产

目录约定（默认 `<数据目录>/honeypot/templates`，可用 `dir` 指定）：

```
templates/
└── grafana/                  # 目录名 = 监听器名 = 模板名
    ├── template.toml
    └── page.html             # http 模板的页面文件
```

`template.toml`（http 模板示例）：

```toml
protocol    = "http"     # http | ssh | telnet
port        = 3000       # 模板监听器端口（与已有监听器冲突会被拒绝）
page        = "page.html"          # 页面文件（相对模板目录）
form_user   = "user"     # 登录表单用户名字段名（逗号分隔可多个，进凭证采集）
form_pass   = "password" # 登录表单口令字段名
decoy_paths = ["/api/admin", "/api/health"]   # 敏感路径（403 诱饵）
```

ssh / telnet 模板用 `banner = "..."` 覆盖对应协议的对外标识（优先级高于
`[honeypot.fingerprint]` 全局值）。

行为约定：

- **单模板损坏只拒绝该模板并告警**，不影响其他模板与内置默认（整包加载
  哲学的单模板化）；
- 模板**内容**变更（页面/表单字段/banner）约 5 秒内自动热重载；
- **增删模板目录 = 监听器增删，需重启**——轮询检测到会告警提示；
- 「不改一行代码，放一个 html + toml 即新增一个假 Grafana 登录页」指的
  就是以上流程（重启一次生效）。

## 三、端口与混布建议

- 默认监听端口是**非特权高位端口**（2222/8081/2323/1337）。要监听 22/80/23
  等标准端口必须以管理员/root 运行——意味着蜜罐进程提权，请权衡后使用，
  更稳妥的方式是上游 NAT/端口转发把 22 映射到 2222。
- 演示端口 2222/8081/2323/1337 **不得直接用于生产伪装**：它们出现在默认
  配置与文档里，等于公开的蜜罐指纹。生产部署请改到你自己环境合理的位置，
  并配合模板自定义页面。
- 真实业务端口混布：蜜罐端口与真实服务端口出现在同一网段/主机时，先想清
  「这台机器为什么会有 MySQL 又有 GitLab」。诱捕面要有可信的业务叙事。
- 任何情况下不要把蜜罐指给真实业务的下游（数据库、内网认证）——蜜罐是
  只进不出的单向面。

## 四、反识别残余风险（诚实声明）

- 不承诺对抗**主动交互式指纹探测**：协议栈行为差异（TCP 时序、选项、
  错误分支的返回）无法通过 banner 配置归零。
- `nmap -sV` 能识别到所配置版本，但深度服务探测（`--version-intensity 5+`
  的探针交互）可能暴露仿真边界——假 Shell 有命令白名单，超出范围返回
  bash 风格错误的集合是有限的。
- 已知安全边界同 README「已知限制」：蜜罐是仿真不是真机，永远不执行
  攻击者输入。

## 五、数据面文件位置（运维自查）

| 文件 | 内容 | 权限 |
